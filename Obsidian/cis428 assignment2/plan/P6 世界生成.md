# P6 世界生成

> 狀態：🟢 已定案
> 對應遊戲節點：[[N4 玩家可自由行動]]、[[N5 建造模式入口]]

## 目標

生成遊戲世界：可編輯區塊、周圍地形、延伸平面、世界邊界、霧。

## 空間模型

實際尺寸由 `DEFAULT_WORLD_GEN_CONFIG` 決定：`chunkSize = 16`、`editableRadius = 0`、`solidRadius = 1`、`playableRadius = 2`。
半徑單位是 **chunk 數**，不是格數。換算方式見下方「區域規格」。

```
┌──────────────────────────────────────────────────┐
│  世界邊界牆：4 面，x/z = -32 與 48 的平面         │
│  （y 0 → 256，灰階斜線貼圖 × 藍色）               │
│  ┌────────────────────────────────────────────┐  │
│  │  玩家活動範圍：5×5 chunk = 80×80 格         │  │
│  │  x/z = -32 ~ 47                             │  │
│  │  ┌──────────────────────────────────────┐  │  │
│  │  │  實體方塊：3×3 chunk = 48×48 格       │  │  │
│  │  │  x/z = -16 ~ 31（不可互動）           │  │  │
│  │  │  ┌────────────────────────────────┐  │  │  │
│  │  │  │  可編輯：1 chunk = 16×16 格     │  │  │  │
│  │  │  │  x/z = 0 ~ 15                  │  │  │  │
│  │  │  │  唯一被 carve 的區域           │  │  │  │
│  │  │  └────────────────────────────────┘  │  │  │
│  │  └──────────────────────────────────────┘  │  │
│  └────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────┘
```

## 區域規格

| 區域 | 範圍（格子） | 內容 | 可互動 | 節點 |
|---|---|---|---|---|
| 可編輯區 | `x/z = 0..15` | 完整方塊，中心被 carve 成坑（基巖在 `y = 0`） | ✅ | `VoxelChunkNode` |
| 實體環 | `x/z = -16..31` | 完整方塊，**不 carve** | ❌ | `VoxelChunkNode`（唯讀） |
| 活動環 | `x/z = -32..47` | 只有頂層平面 | ❌ | `VoxelChunkNode`（唯讀） |
| 世界邊界 | `x/z = -32` 與 `48` | 4 面垂直牆，`y = 0..256` | ❌ 阻擋 | `MeshNode` × 4（`WorldBorder`） |

> **只有 `editableRadius` 範圍內的 chunk 會被 carve**（`hasCarvedCenter && isEditableChunk`）。
> 所以外側 8 個 chunk 是完整的地形，玩家挖不穿也走不過去 —— 最終只有 chunk `0` 有一個坑。

> **注意 off-by-one**：`editableRadius = 0` 的範圍是 `0..15`，**不是** `-16..15`。
> 算式是 `minX = -radius*size`、`maxX = radius*size + size - 1`。
> 舊版用 `limit = (radius + 1) * size` 導致多跨一個 chunk，詳見 [[ISSUE-007 可編輯範圍與基巖高度與世界邊界]]。

## 生成參數

```typescript
export const DEFAULT_WORLD_GEN_CONFIG: WorldGenConfig = {
  chunkSize: 16,
  editableRadius: 0,      // 0 → 16×16（單一 chunk）
  solidRadius: 1,         // 1 → 48×48（3×3 chunk）
  playableRadius: 2,      // 2 → 80×80（5×5 chunk）
  surfaceY: 10,           // 草地層
  minY: 0,
  maxY: 255,
  surfaceBlock: BLOCK_GRASS,
  subSurfaceBlock: BLOCK_DIRT,
  carveCenterDepth: 0,    // 預設不挖
};

/** 遊戲實際使用的設定：坑底 = 世界底 */
export const PIT_FLOOR_Y = DEFAULT_WORLD_GEN_CONFIG.minY;   // 0

export const GAMEPLAY_WORLD_GEN_CONFIG: WorldGenConfig = {
  ...DEFAULT_WORLD_GEN_CONFIG,
  carveCenterDepth: DEFAULT_WORLD_GEN_CONFIG.surfaceY - PIT_FLOOR_Y,   // 10
};
```

`carveCenterDepth = 10` 讓 `carvedFloorY = surfaceY - 10 = 0`，也就是坑底那一層就是世界最底層，`blockIdForCarvedColumn` 會把它放成 `BLOCK_BEDROCK`（受保護，`isProtectedBlock` 會拒絕 break 與 place）。

## 生成流程

```
MyGameMode.buildWorld()
  → generateWorld(world, GAMEPLAY_WORLD_GEN_CONFIG)      // 5×5 chunk，只 carve 中心
  → WorldBorder.create().build(borderExtentForRadius(2, 16), GAMEPLAY_WORLD_GEN_CONFIG)
  → world.add(worldBorder)
  → applyFog(world.getRenderScene())
  → new BuildController({ bounds: buildBoundsForRadius(editableRadius, chunkSize), ... })
```

`onAfterEndPlay()` 會 `worldBorder.destroy()` 並清掉參考，避免重進 Play 時疊出第二組牆。

## 邊界牆實作

三個檔案，刻意把純數學與引擎物件分開，讓幾何可以在無場景的環境下單元測試：

| 檔案 | 職責 |
|---|---|
| `src/world/borderSpec.ts` | 牆的位置／尺寸／淡出曲線，零依賴 |
| `src/world/worldBorderTexture.ts` | 程序化灰階斜線遮罩（`buildBorderPixels` 純函式） |
| `src/world/WorldBorder.ts` | 4 個 `MeshNode`，材質、UV 捲動、逐牆距離淡出 |

### 幾何

`borderWallSpecs` 產生 4 面牆，**中心落在邊界平面上**（不是推到外面），這樣玩家還是可以站在最外側那一格，牆讀起來是「地面的邊」而不是一個提早一米的隱形圍欄。

- 南北牆跨滿 X（`sizeX = 80`），東西牆跨滿 Z（`sizeZ = 80`）
- 厚度 `BORDER_WALL_THICKNESS = 0.5`
- 高度 `borderWallHeight = maxY + 1 - minY = 256`，中心 `y = 128`

**為什麼用 `BoxGeometry` 而不是 voxel**：一面牆 80×256 米，用 voxel 是 20k 格／面，而且每次 chunk 重建都要重算 collider。用 box 是 12 個三角形 + 一個 `BoundingBox` collider（`PrimitiveNode.overridePhysicsOptions`）。

### 貼圖

**32×32、8 級漸層**的灰階斜線遮罩：

```
BORDER_TILE_SIZE   = 32
BORDER_BAND_COUNT  = 2      // 每個 tile 兩條斜帶 → period 16
BORDER_BAND_ALPHAS = [255, 245, 228, 205, 176, 142, 104, 62]
alpha(x, y) = ALPHAS[(x + y) % 16]  // 前 8 個 texel 走 ramp，後 8 個全透明
RGB 固定 255（白色）→ 色相完全由 material.color 決定
```

> 為什麼不是 16×16 的原始尺寸：4 級漸層在 45 度邊緣會出現明顯階梯，實機截圖看得出來。

### 材質

```typescript
new THREE.MeshBasicMaterial({
  map: texture,
  color: 0x20a0ff,        // Minecraft 靜止狀態的邊界藍
  transparent: true,
  depthWrite: false,      // 半透明，不要寫深度
  side: THREE.FrontSide,
  fog: false,             // 見下方
  toneMapped: false,
});
```

**顏色為什麼放在 `material.color` 而不是烤進貼圖**：這是 Minecraft 的做法 —— 一張灰階 `forcefield.png`，執行時乘上藍／綠／紅對應靜止／擴展／收縮。把藍色烤進貼圖會變成「藍 × 藍」而變暗。

**三個實機驗證才發現的必要設定**：

| 設定 | 不設會怎樣 |
|---|---|
| 不用 `AdditiveBlending` | 加法只會讓背後變亮，而天空接近白色 → 白色 + 藍 = 白色，牆在天空上完全消失（只在穿過草地處可見） |
| `fog: false` | `scene.fog` 會把整面牆混成一片平霧，斜線被洗掉 |
| `depthWrite: false` | 半透明牆會遮住後面的地形 |

淡出改由 `borderAlphaForDistance` 自己做（`BORDER_FADE_NEAR = 40`、`BORDER_FADE_FAR = 100`），因為它可控、可以逐面牆不同，而且不會被霧的設定綁住。

### 動畫

`tickPrePhysics` 每幀 `texture.offset.y` 捲動 `BORDER_SCROLL_TILES_PER_SECOND = 0.3`（一 tile = 4 米，所以一個 tile 約 3.4 秒通過一點），並依相機到各牆的距離更新 `material.opacity`；`opacity < 0.01` 的牆連 `visible` 都關掉。

## 玩家出生點

**已定案：出生點由場景中的 `Player Start` 節點（Empty Object）決定，不寫死在程式碼裡。**

| 項目 | 值 | 說明 |
|---|---|---|
| 節點類型 | `ENGINE.PlayerStart` | 場景中的 Empty Object，編輯器顯示青色箭頭 |
| 節點名稱 | `Player Start` | 目前場景已存在 |
| 目前座標 | `(9, 0.9, -12.5)` | 暫時位置，位於可編輯區塊外側 |
| 朝向 | 節點自身的 `rotation` | 箭頭方向 = 玩家面向 |
| 調整方式 | **在編輯器拖動節點** | 隨時可改，不需改程式碼 |

### 引擎的出生流程（已確認）

```
GameMode.onPlayerJoined(clientId)
  → spawnPlayerControllerForClient()
  → handleNewPlayer(controller)
  → restartPlayer(controller)
  → findPlayerStart(controller)          // world.getNodes(PlayerStart)
  → adjustSpawnPositionForPlayerStart()  // 若被佔用，隨機偏移 2 單位
  → spawnPlayerPawnWithTransform()       // pawn.setWorldPosition(spawnPosition)
```

**關鍵事實**：

- `findPlayerStart()` 會**隨機挑一個未被佔用的 `PlayerStart`** —— 場景中只能放**一個**，否則出生點不確定
- `adjustSpawnPositionForPlayerStart()` 在出生點半徑 1.5 內有 pawn 時會隨機偏移 2 單位
- `PlayerStart` 的 `canEverTick = false`，純標記節點，不參與 tick
- 座標是**膠囊中心**（`y = 0.9` 表示站在 `surfaceY = 0` 的地面上）

### 實作注意

- **不要**在 `MyGameMode` 覆寫 `findPlayerStart()` —— 引擎預設行為已足夠
- **不要**在 `MyCharacterPawn` 寫死出生座標 —— 會與 `PlayerStart` 衝突
- 若之後要「重生」功能，呼叫 `controller.restartPlayer()` 即可回到 `PlayerStart`

## 風險

| 風險 | 緩解 |
|---|---|
| 周圍一圈方塊太多 | 只生成表面，或拆成多 chunk |
| 邊界牆穿模 | `BoundingBox` 靜態碰撞（`overridePhysicsOptions`）—— 已實機 raycast 驗證 |
| 邊界牆在天空上看不見 | 不用加法混合、`fog: false`、`alpha` 混合 —— 三項必須同時存在 |
| 邊界牆被霧洗掉 | 材質 `fog: false`，淡出改由 `borderAlphaForDistance` 控制 |
| 霧太濃看不到區塊 | 調整 `fogNear`/`fogFar` |
| 出生點在區塊內導致卡住 | 出生在區塊外側，且 `surfaceY` 上方留空 |
| 場景有多個 `PlayerStart` 導致出生點隨機 | **只放一個** `Player Start` 節點 |
| 重進 Play 疊出第二組邊界牆 | `onAfterEndPlay()` 內 `worldBorder.destroy()` |
| 出生點 `y` 設錯導致掉進地面 | `y = surfaceY + CHARACTER_HEIGHT / 2 = 0.9` |
