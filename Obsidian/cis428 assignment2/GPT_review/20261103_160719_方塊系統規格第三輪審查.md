## 仍未解決的問題

### 1. Neighbor update 不會重算被直接編輯的格子 — High

`updateNeighbors()` 只處理 seed 的六個鄰居，沒有重新計算 seed 本身。新增的樓梯、欄杆或 undo/redo 編輯可能保留錯誤的初始 state，無法達到 fixed point。

**修正：** 將編輯格與鄰居全部加入 worklist，或明確規定 seed 必須先執行 `computeState()`。

### 2. Registry 持久化契約仍不完整 — High

目前只有 `key` 與 `findByKey()`，但缺少完整的：

- save schema
- registry version
- key canonicalization
- unknown-block fallback
- version migration
- 載入錯誤策略

**修正：** 定義完整存檔與 registry migration 契約。

### 3. 兩份文件的 canonical phase order 仍矛盾 — High

重構設計與實作規格對 Registry、`VoxelShape`、collision、non-full block 及 step-up 的順序仍不同。

**修正：** 建立唯一 canonical phase table，另一份文件只引用該表，不再各自維護順序。

### 4. `BlockType` API 定義不一致 — High

3.1 的 `BlockType` 沒有 `renderShape()` 與 `computeState()`，但後續章節又依賴這些方法。直接依早期介面實作會造成後續 mesher 與 neighbor update 無法使用必要 API。

**修正：** 合併為單一完整介面，清楚標示必填與選填欄位。

### 5. Multi-box rendering 的內部面與面積 union 未定義 — Medium

目前仍可能對每個 box 產生六面，沒有定義同一 shape 內部面剔除、面積 union、跨方塊部分遮蔽與 cross geometry。

**修正：** 定義內部面剔除規則、同面區間 union、render type 與第一版允許的近似範圍。

### 6. DDA tie policy 仍不完整 — Medium

雖然加入 `TIE_EPSILON`，但 corner/edge tie 時的 traversal 與 normal 優先序仍依實作迴圈順序間接決定，且 API 未限制最大射程。

**修正：** 將 tie traversal、normal priority、epsilon 與最大射程寫成正式契約並加測試。

### 7. 碰撞方案命名在兩份文件相反 — Medium

設計文件與實作規格對方案 A/B 的定義相反，可能導致 API Spike、記憶體評估與 fallback 被錯誤實作。

**修正：** 統一方案名稱，或改用 `VoxelSubdivision`、`DualMeshNode` 等具體名稱。

### 8. Collider remove/rebuild 缺少正式生命週期契約 — Medium

雖然已修正 `removeNode()` 的描述，也提出 remove → override → re-register 順序，但尚未定義：

- rebuild 後 node/body 的 postcondition
- 重複 rebuild 行為
- 失敗回復

**修正：** 將生命週期流程定義為唯一 API contract，並加入編輯、移除、重建後的 collider/raycast 測試。

### 9. 細薄碰撞形狀仍沒有正式方案 — High

文件已指出 `SUBDIVISION=2` 對柵欄、火把等形狀不可靠，但尚未決定正式解法。雙 MeshNode 方案又依賴尚未完成的 collider Spike。

**修正：** 在 non-full block 實作前完成正式碰撞方案 Spike，不應將未標示的碰撞膨脹視為正式行為。

### 10. 設計文件的 DDA 範例仍不可直接實作 — Medium

設計文件的函式簽名仍接收 `VoxelVolume`，但內容使用未宣告的 `world.isLoaded()` 與 `world.getBlock()`，且未同步實作規格的輸入驗證與 tie epsilon。

**修正：** 以實作規格的 `VoxelRaycastWorld` API 取代舊 DDA 範例。

## 最終建議

目前仍不建議進入正式實作。

開始實作前必須先：

- 統一 phase order 與 `BlockType` API
- 補齊 registry/serialization/unknown block 契約
- 修正 seed neighbor recompute 與 fixed-point worklist
- 完成 multi-box rendering 規則
- 決定細薄方塊的正式碰撞方案
- 完成 collider lifecycle/API Spike
- 統一兩份文件的 DDA API

完成以上 Phase 0 工作後，才建議開始 `VoxelShape` 與基本 shape 單元測試。
