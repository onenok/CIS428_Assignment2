# 第 2 層 — 引擎整合測試

> 在 Node 中跑真正的引擎（headless 模式），驗證引擎 API 與生命週期。

---

## 為什麼可行

引擎有內建 headless 模式：

- `GameLoop.ts:262` — `this.headless = options.headless ?? (NetRuntime.isDedicatedServer() || isNode())`
- `World.ts:217-223` — 無 container 時 `new UIManager({})`，不建立 DOM
- `InputManager.ts:500` — `attachListeners: false` 時不綁事件
- `SceneNode` / `VoxelMeshNode` — grep `document.` / `window.` 零命中
- Rapier WASM 內嵌在 `rapier.mjs`（base64），`init()` 無參數

---

## 共用輔助：`tests/world/headlessWorld.ts`

### `createHeadlessWorld(options?)`

建立 headless `World` + 真實 Rapier 物理引擎。

```typescript
const handle = await createHeadlessWorld();
try {
  // 測試內容
} finally {
  handle.dispose();
}
```

回傳 `{ world, physics, dispose }`。

**關鍵細節**：注入一個最小 gameLoop 樁，因為 `SceneNode.getPhysicsEngine()`
讀的是 `world.gameLoop.physicsEngine`，而真正的 `BaseGameLoop` 需要
`HTMLElement`。

### `addAndBeginPlay(world, node)`

`World.add()` 不會註冊 TickManager，`beginPlay()` 才會。

### `advanceTicks(world, seconds)`

推進 TickManager，用於測試節流與生命週期。

### `stepPhysics(physics, steps?)`

推進物理引擎。**Rapier 只在 `step()` 時索引新 collider**，剛加完節點就
raycast 會回 `null`。

## 現有測試

### `tests/world/smoke.engine.ts`

最基礎的可行性驗證。**先跑這個**，失敗就代表第 2 層不可行。

| 測試 | 驗證 |
|---|---|
| 引擎 import | `@gnsx/genesys.js` 在無 DOM 下可載入 |
| 核心類別 | `World` / `SceneNode` / `GameMode` / `MathHelpers` 存在 |
| `isNode()` | 引擎正確偵測 Node 執行環境 |
| Rapier 初始化 | WASM 可載入 |
| Rapier 世界 | 可建立、可 step、可 free |

### `tests/world/World.engine.ts`

World 生命週期。

| 測試組 | 覆蓋 |
|---|---|
| 建構 | 無 renderer 可建構、`uiManager` 存在、只有內建粒子管理器 |
| 節點生命週期 | 加入、按名查找、tick、`setTickInterval` 節流 |
| 物理 | 引擎可用、raycast 可呼叫 |

**節流測試的意義**：`setTickInterval(0.05)` 在 0.5 秒內應觸發約 10 次。
這驗證了 `TickManager.ts:83-93` 的累加器邏輯（含餘數保留，避免漂移）。

### `tests/voxel/VoxelMeshNode.engine.ts`

引擎內建 voxel 節點。

| 測試 | 驗證 |
|---|---|
| 建立 | 無 renderer 可建立 |
| 程式化資料 | `initializeVoxel()` 接受 `Uint16Array` |
| 讀寫 | `setVoxel()` / `getVoxel()` 往返一致 |
| 建網格 | `buildMesh()` 產生幾何 |
| 單一方塊 | 36 個頂點（6 quad × 6 頂點） |
| 實心立方體 | 也是 36 個頂點（合併成 6 quad） |

**為什麼測這個**：這是自建 `VoxelChunkNode` 的參考基準。如果引擎內建的
行為和我們的理解不符，自建版本也會錯。

### `tests/build/raycast.engine.ts`

物理射線 —— 建造系統選取方塊的基礎。

| 測試組 | 覆蓋 |
|---|---|
| 單一方塊 | 命中位置、法向量、距離、`hitNode` |
| 超出範圍 | 回 `null` |
| 最近優先 | 兩個方塊取近的 |
| 忽略節點 | `ignoredNodes` 生效 |
| 收集全部 | `raycastAll` 按距離排序 |
| 放置數學 | 命中點 + 法向量 → 相鄰格 |
| 破壞數學 | 命中點 − 法向量 → 目標格 |

### `tests/character/firstPerson.engine.ts`（待建立）

第一人稱渲染機制 —— 驗證 `setHiddenInGame` 與相機位置。

| 測試組 | 覆蓋 |
|---|---|
| 眼高 | `cameraPivot.position.y === 0.7` |
| 相機在 pivot 內 | `getInitialCameraPositions()` 回相同座標 |
| 隱藏本體 | `setHiddenInGame(true)` → `hiddenInGame === true` |
| 顯示本體 | `setHiddenInGame(false)` → `hiddenInGame === false` |
| 編輯器不受影響 | `world.isEditorWorld === true` 時 `layers` 不變 |
| 影子保留 | `hiddenInGame` 不影響 `castShadow` |

**注意**：`applyHiddenInGameRendering()` 在 `world.isEditorWorld` 時直接 return，
所以 headless 測試要斷言 `hiddenInGame` 旗標本身，而非 `layers`。

## 已知陷阱

| 陷阱 | 症狀 | 解法 |
|---|---|---|
| 節點沒 tick | `ticks === 0` | 用 `addAndBeginPlay()` |
| raycast 回 null | collider 存在但打不到 | 先 `stepPhysics()` |
| `getRootNodes()` 不為空 | 預期 0 得到 1 | `GlobalParticleManager` 是內建的 |
| `getPhysicsEngine` 不存在 | `world.getPhysicsEngine is not a function` | 走 `world.gameLoop.physicsEngine` |
| collider 是空殼 | `shape.type = 9`、`halfExtents` undefined | `collisionMeshType: 'boundingBox'` |
| `Vector` 沒有 `toArray` | `options.gravity.toArray is not a function` | 用 `THREE.Vector3` |
| 測試綠但 build 紅 | `TS2740: Type 'Vector' is missing ...` | 每次新增測試後跑 `pnpm build` |
| 找不到 Rapier 型別 | `TS2307: Cannot find module '@dimforge/rapier3d-compat'` | 走 `ENGINE.createPhysicsEngine()` |
| enum 用字串 | `TS2322: not assignable to CollisionMeshType` | 用 `ENGINE.CollisionMeshType.BoundingBox` |

## 執行

```powershell
pnpm verify:engine
```

首次執行約 5 秒（引擎載入），之後每個測試 10–70 ms。

---

## 新增第 2 層測試的時機

- 用了引擎 API，但不確定行為
- 需要真實物理（碰撞、raycast、重力）
- 需要真實生命週期（`beginPlay` / `endPlay` / tick）
- 需要真實場景樹（父子關係、查找）

**不要**為了測純邏輯而用第 2 層 —— 慢十倍且訊息更難讀。
