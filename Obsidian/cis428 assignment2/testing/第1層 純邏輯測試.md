# 第 1 層 — 純邏輯測試

> 不載入引擎，只測演算法與資料結構。毫秒級完成。

---

## 特性

- **零引擎依賴**：只 import 被測模組本身
- **零 DOM 依賴**：純函式、純資料
- **極快**：全部跑完 < 10 ms
- **失敗訊息精準**：沒有引擎堆疊干擾

## 現有測試

### `tests/voxel/faceCulling.unit.ts`

驗證面剔除規則 —— 建造系統的核心。

| 測試組 | 覆蓋 |
|---|---|
| 單一方塊 | 孤立方塊顯示 6 面 |
| 相鄰方塊 | 共享面被剔除（12 → 10） |
| 完全包圍 | 中心方塊 6 面全隱藏 |
| 實心立方體 | 3×3×3 只產生 54 面 |
| 空心殼 | 外 54 + 內 6 = 60 面 |
| 體積邊界 | 越界鄰居視為空氣 |
| 幾何輔助 | 4 角、單位法向量、正確側面 |
| 存取器 | z-major 索引、越界寫入被拒 |

**為什麼重要**：使用者明確要求「不會看得到的面不會顯示」。這條規則一旦回歸，
效能會直接崩掉（每個方塊 6 面 vs 只顯示外殼）。

### `tests/voxel/greedyMesh.unit.ts`

驗證貪婪合併演算法。

| 測試組 | 覆蓋 |
|---|---|
| 單一方塊 | 6 個面積 1 的 quad |
| 合併 | 4×4 平板、實心立方體頂面合併成 1 個 quad |
| 不合併 | 不同材質、中間有缺口 |
| 內部面 | 實心立方體 6 quad、空心殼 60 面積 |
| quad 位置 | 邊界正確、原點在範圍內 |

**為什麼重要**：雖然建造系統不做 greedy 合併（每塊保留自己的貼圖），但這個
演算法是「哪些面存在」的參考實作。測試它等於測試面剔除的第二種表達。

### `tests/voxel/coords.unit.ts`

驗證三種座標空間的轉換。

| 測試組 | 覆蓋 |
|---|---|
| `floorDiv` / `positiveMod` | 負數向負無窮取整、餘數非負 |
| world ↔ voxel | 地板取整、自訂 voxel 大小、往返一致 |
| voxel ↔ chunk | 正負座標分割、local 在範圍內、往返一致 |
| 高度限制 | Y ∈ [-10, 255] 含端點 |
| 可編輯區塊 | 中心 chunk、半徑擴展、高度優先 |
| 鍵值 | 唯一、穩定 |

**為什麼重要**：座標 off-by-one 是最難在編輯器裡 debug 的 bug。負座標尤其
容易錯 —— `Math.trunc(-1/16)` 是 `0`，但正確答案是 `-1`。

### `tests/character/eyeHeight.unit.ts`（待建立）

驗證第一人稱眼高計算 —— 純數學，不需引擎。

| 測試組 | 覆蓋 |
|---|---|
| 眼高比例 | `CHARACTER_HEIGHT × 0.39 ≈ 0.7` |
| 相機在膠囊內 | `0 < eyeHeight < CHARACTER_HEIGHT / 2` |
| 視覺模型偏移 | `-CHARACTER_HEIGHT / 2 = -0.9` |
| 相機不在地面下 | `eyeHeight > 0` |

**為什麼重要**：眼高算錯會讓相機卡在模型內部（看到頭部內壁），
這是最容易「看起來像 bug 但其實是參數錯」的地方。
