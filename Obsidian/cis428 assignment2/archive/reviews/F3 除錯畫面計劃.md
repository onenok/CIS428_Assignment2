## 一、問題陳述

目前無法確認 `PlayerStart` 的 Y 值是否正確，因為：

1. 使用者看不到 Play mode 的即時數值
2. 截圖只能看到「畫面」，看不到「座標」
3. 每次改完都要重新 Play、截圖、我推理、再改 —— 循環太慢

**需要的是一個 Minecraft F3 式的除錯畫面。**

## 二、設計目標

| 目標 | 說明 |
|---|---|
| 一鍵開關 | `F3` 切換顯示／隱藏 |
| 零依賴 | 不引入新套件，用引擎已有的 `UIElement` |
| 不干擾遊戲 | 面板 `pointer-events: none`，不搶滑鼠 |
| 可擴充 | 之後要加新欄位只需改一個陣列 |
| 生產安全 | 用引擎既有的 `shouldCreateGameLoopDebugUI()` |

## 三、顯示內容

### 第一區：玩家（最重要）

```

Block: 0 / 11 / 0
Chunk: 0 / 0
Facing: north (yaw 180.0°)
```

**為什麼這些**：

- `Grounded` — **關鍵**：若為 `false` 表示玩家在自由落體，碰撞體沒生效
- `Velocity` — 若 Y 速度持續負值，表示正在往下掉

**為什麼這些**：

## 四、修正後的實作方案

### 4.1 檔案結構

```
src/debug/
  DebugSnapshot.ts       ← 型別 + 資料收集（純函式，可測試）
  debugFormat.ts         ← 格式化（純函式，可測試）
  DebugOverlay.ts        ← 面板本體（UIElement 包裝）
tests/debug/
  debugSnapshot.unit.ts  ← 資料收集測試（純函式）
  debugFormat.unit.ts    ← 格式化測試（純函式）
```

### 4.2 【修正 1】pointer-events 被覆寫

**問題**：`UIManager.createElement()` 在 `UIManager.ts:69` 無條件執行：

```ts
element.setStyle('pointerEvents', 'auto');
```

所以 `UIElementOptions.style` 裡的 `pointerEvents: 'none'` 會被覆寫。

**修正**：建立後**再呼叫一次** `setStyle()`：

```ts
const element = ui.createElement(DEBUG_OVERLAY_ID, {
  style: DEBUG_OVERLAY_STYLES,
});
// createElement() forces pointerEvents to 'auto' — override it afterwards.
element.setStyle('pointerEvents', 'none');
```

**驗證方式**：`DebugOverlay` 提供 `get pointerEvents(): string` getter，測試斷言為 `'none'`。

### 4.3 【修正 2】欄位名稱

**問題**：計劃用了不存在的 `flow.phase`、`targetCell`。

**查證結果**：

| 計劃寫的 | 實際 API | 位置 |
|---|---|---|
| `flow.phase` | `flow.currentPhase` | `GameFlow.ts:84` |
| `targetCell` | `hoveredCell` / `previewCell` | `MyGameMode.ts` |

**修正**：全部改用實際名稱。

### 4.4 【修正 3】Grounded 與 Velocity

**查證結果**：

```ts
// CharacterMovementNode.ts:364 — public
public getGrounded(): boolean {
  return this.isGrounded || (performance.now() - this.lastGroundedTime < this.coyoteTimeMs);
}

// CharacterMovementNode.ts:376 — public
public getVelocities(): { forward: number, right: number, vertical: number } {
  return { forward: this.forwardVelocity, right: this.rightVelocity, vertical: this.verticalVelocity };
}
```

**所以 `isGrounded` 雖然是 `protected`，但 `getGrounded()` 是 `public`。** 審查說「受保護」只對了一半。

**但 `getVelocities()` 回傳的是本地座標**（forward / right / vertical），不是世界座標。

**修正**：在 `DebugSnapshot.ts` 內做轉換：

```ts
/** Converts local forward/right/vertical speeds into a world-space vector. */
export function localVelocitiesToWorld(
  velocities: { forward: number; right: number; vertical: number },
  yawRadians: number,
): { x: number; y: number; z: number } {
  const sin = Math.sin(yawRadians);
  const cos = Math.cos(yawRadians);
  return {
    x: velocities.forward * sin + velocities.right * cos,
    y: velocities.vertical,
    z: velocities.forward * cos - velocities.right * sin,
  };
}
```

**這是純函式，可以完整單元測試**（不需要 DOM）。

**若 `getMovementNode()` 拿不到 `CharacterMovementNode`**（例如 `FlyingMovementNode` 繼承鏈不同），則 fallback 顯示 `n/a`。

### 4.5 【修正 4】Draw calls / Triangles — 可以保留

**查證結果**：`collectPerformanceSnapshot()` 是重量級函式（含 texture VRAM 估算），不適合每幀呼叫。但**底層 API 可以輕量讀取**。

**完整呼叫鏈（已查證）**：

```ts
// 1. World 有 getRenderer()
//    .engine/src/game/World.ts:1416
public getRenderer(): IGenesysRenderer | null

// 2. IGenesysRenderer 沒有 native，但有 asWebGL() / asWebGPU()
//    .engine/src/render/IGenesysRenderer.ts
asWebGL(): THREE.WebGLRenderer | null;
asWebGPU(): WebGPURenderer | null;

// 3. PerformanceSnapshot.ts:302-320 就是這樣做的
function readRenderStats(renderer: IGenesysRenderer): PerformanceSnapshotRender {
  const native = renderer.asWebGL() ?? renderer.asWebGPU();
  if (!native) { return { drawCalls: 0, triangles: 0, ... }; }
  const isWebGL = renderer.asWebGL() !== null;
  const renderInfo = native.info.render;
  return {
    drawCalls: isWebGL ? renderInfo.calls : (renderInfo as { drawCalls?: number }).drawCalls ?? 0,
    triangles: renderInfo.triangles,
    ...
  };
}
```

**所以 Draw calls / Triangles 可以保留**，用輕量版本：

```ts
/** Reads draw-call stats straight from the renderer, or `null` when unavailable. */
export function readRenderStats(
  renderer: ENGINE.IGenesysRenderer | null,
): { drawCalls: number; triangles: number } | null {
  if (!renderer) return null;
  const native = renderer.asWebGL() ?? renderer.asWebGPU();
  if (!native) return null;
  const info = native.info.render;
  const isWebGL = renderer.asWebGL() !== null;
  return {
    drawCalls: isWebGL
      ? (info as { calls: number }).calls
      : ((info as { drawCalls?: number }).drawCalls ?? 0),
    triangles: info.triangles,
  };
}
```

**`MyGameMode` 取得 renderer 的方式**：`this.getWorld()?.getRenderer() ?? null`。

**注意**：`readRenderStats()` 需要 `IGenesysRenderer` 實例，**無法在無 DOM 的 unit test 內測試**。改為測試它的 `null` 分支（傳 `null` 應回傳 `null`）。

### 4.6 【修正 5】Production gate

**審查說「`shouldCreateGameLoopDebugUI()` 不存在」→ 不成立。**

查證：

```ts
// .engine/src/utils/Utils.ts:347
export function shouldCreateGameLoopDebugUI(): boolean {
  return !isPublishedGame() || isGenesysDebugEnabled();
}

// .engine/src/utils/index.ts:7
export * from './Utils.js';

// .engine/src/index.ts:10
export * from './utils/index.js';
```

**所以 `ENGINE.shouldCreateGameLoopDebugUI()` 可以直接用。**

**但審查的另一半是對的**：`?debug=1` 會讓 production 暴露除錯 UI。

**修正**：**不用 `?debug=1`**，直接用引擎的 gate：

```ts
import * as ENGINE from '@gnsx/genesys.js';

/** True when the F3 overlay should be created at all. */
export function shouldCreateDebugOverlay(): boolean {
  return ENGINE.shouldCreateGameLoopDebugUI();
}
```

這樣行為與引擎的 stats.js 面板完全一致：未發佈版永遠有，發佈版需要 `window._genesys_debug_ === true`。

**測試**：`shouldCreateDebugOverlay()` 是純函式（只讀 `window`），可在 unit test 內 mock `globalThis.window`。

### 4.7 【修正 6】Lint 指令

**審查說「`pnpm lint` 會 `--fix`，不是唯讀驗證」→ 屬實。**

```json
"lint": "eslint . --fix --ext .ts,.tsx"
```

**但 `AGENTS.md:100` 明確寫**：

> You **must** use `pnpm lint` to detect and auto-fix linting issues.

**所以這是專案規範，不是錯誤。** 我會繼續用 `pnpm lint`，因為：
1. `AGENTS.md` 是專案的強制規範
2. `--fix` 只改格式，不改語意
3. 改完後 `pnpm build` 會驗證編譯

**但為了讓使用者能「唯讀檢查」**，我在計劃內註明替代指令：

```powershell
pnpm exec eslint . --ext .ts,.tsx
```

### 4.8 【修正 7】測試策略

**審查要求「加入 F3 按鍵、顯示切換、overlay lifecycle 與實際遊戲狀態的整合測試」→ 部分可行。**

**查證結果**：測試環境**沒有 DOM**（`package.json` 無 jsdom / happy-dom，`harness.ts` 無 `document` / `window` 注入）。

現有 UI 測試（`uiWiring.unit.ts`）的做法是**只驗常數與純函式**：

```ts
it('puts the hotbar at the bottom centre', () => {
  assertEqual(BUILD_UI_POSITIONS.hotbar, 'bottom-center');
});
```

**所以無法測 DOM 行為**（`pointer-events`、`show()` / `hide()`、`preventDefault()`）。

**修正後的測試策略**：

| 測試類型 | 可測 | 做法 |
|---|---|---|
| 格式化 | ✅ | `formatDebugSnapshot()` 純函式 |
| 座標計算 | ✅ | `localVelocitiesToWorld()`、`worldToBlock()`、`worldToChunk()` |
| 樣式常數 | ✅ | 斷言 `DEBUG_OVERLAY_STYLES.pointerEvents === 'none'` |
| Production gate | ✅ | mock `globalThis.window` |
| 按鍵綁定 | ✅ | 斷言 `KEY_BINDINGS.toggleDebugOverlay` 含 `'F3'` |
| **DOM 行為** | ❌ | **無 jsdom，測不了** |
| **overlay lifecycle** | ❌ | **無 DOM，測不了** |

**所以「overlay lifecycle 整合測試」做不到**，除非引入 jsdom。引入 jsdom 會：
- 增加依賴（違反「零依賴」目標）
- 需要改 `harness.ts`（影響 577 個現有測試）

**決定**：**不引入 jsdom**。改為：
1. 純函式測試（12+ 個）
2. 常數斷言測試
3. **在編輯器 Play 手動驗證** DOM 行為（列在驗收標準）

### 實作時遇到的問題

**`switch` 型別窄化**：`handleAction()` 內 `toggleDebugOverlay` 已在 `switch` 前提前 `return`，TypeScript 因此把它從 `switch` 的 union 中移除。在 `switch` 內再加 `case 'toggleDebugOverlay'` 會報 `TS2678`。已移除多餘的 `case`。

**`formatDebugSnapshot()` 行數不一致**：`player: null` 時只輸出 1 行，有 pawn 時輸出 6 行，導致面板高度跳動。已改為 `null` 時也輸出 6 行 `n/a`。

## 六、風險與注意事項

| 風險 | 對策 |
|---|---|
| `F3` 被瀏覽器攔截 | `handleKeyDown()` 內 `e.preventDefault()` |
| `pointer-events` 被 `createElement()` 覆寫 | 建立後再 `setStyle('pointerEvents', 'none')` |
| 每幀更新 DOM 造成效能問題 | 只在**可見時**更新；用 `textContent` 而非 `innerHTML` |
| 面板遮住引擎 stats.js | 面板放**右上角**（`top: 8px; right: 8px`） |
| `getMovementNode()` 型別不符 | 用 `instanceof ENGINE.CharacterMovementNode` 判斷，否則顯示 `n/a` |
| 拿不到 renderer | `readRenderStats()` 回傳 `null`，面板顯示 `n/a` |
| 無 DOM 測試環境 | 純函式測試 + 手動 Play 驗證 |
