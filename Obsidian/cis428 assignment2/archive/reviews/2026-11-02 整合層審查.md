### R-04 `placedBlockCount` 會被原生地形破壞操作污染

| 項目 | 內容 |
|---|---|
| 嚴重度 | 🔴 高 |
| 檔案 | `src/voxel/VoxelChunkNode.ts:119-120` |
| 查證結果 | ✅ 屬實，且**比審查說的更嚴重** |

**證據**：

```ts
// VoxelChunkNode.ts:119-120
if (previous === EMPTY && blockId !== EMPTY) this.placedBlockCount++;
else if (previous !== EMPTY && blockId === EMPTY) this.placedBlockCount--;
```

**審查說**「可能錯誤，數值甚至變負」。實際是**必然錯誤**：

玩家挖掉原生地形（`previous = 泥土, blockId = EMPTY`）→ `placedBlockCount--` → **負數**。

而 `evaluateSubmit()` 用 `placedBlockCount > 0` 判斷：

| 玩家行為 | 實際 count | 判定 |
|---|---|---|
| 放 3 格 | 3 | normal ✅ |
| 挖 5 格、放 3 格 | -2 | **blank ❌** |
| 挖 1 格 | -1 | **blank ❌** |

**註解與實作不符**：

```ts
/** Number of non-air voxels the player placed (i.e. excluding generation). */
public getPlacedBlockCount(): number {
  return this.placedBlockCount;
}
```

註解說「excluding generation」，但實作把「破壞原生地形」也算進去了。

**影響**：正常提交可能被誤判為白卷。

## 二、審查漏掉的 3 項

### R-09 `placedBlockCount` 會變負數（R-04 的延伸，但影響不同）

| 項目 | 內容 |
|---|---|
| 嚴重度 | 🔴 高 |
| 檔案 | `src/voxel/VoxelChunkNode.ts` |
| 來源 | 本 session 補 |

R-04 說「會被污染」，但沒說清楚**污染的方向與後果**。

**根因**：`placedBlockCount` 同時承擔兩個語意：

1. 「玩家放了多少方塊」（給 Submit 判斷用）
2. 「目前有多少非空氣方塊是玩家造成的」（給統計用）

破壞原生地形時，語意 1 不該變，但語意 2 該變。單一計數器無法同時滿足。

**修正方向**：分離成兩個計數器，或改用「與生成快照的差異」計算。

## 三、審查的一個盲點

審查說：

> 測試通過不代表設計完整，因為目前測試主要驗證底層函式，未覆蓋完整遊戲流程整合。

**這句話對，但沒說出真正的問題。**

577 個測試裡，整合層測試（`tests/integration/gameModeWiring.engine.ts`）驗的是「**物件存在**」而不是「**行為正確**」：

```ts
it('creates a BuildController in replace mode', ...)   // 只驗 !== null
it('exposes the four HUD widgets', ...)                // 只驗欄位存在
it('owns a GameFlow that starts in boot', ...)         // 只驗初始狀態
```

這些測試**永遠不會抓到** R-01（god-view 沒切相機）或 R-02（undo 不重建 mesh），因為它們只檢查 `gameMode.buildController !== null`。

**所以問題不是「測試不夠多」，是「測試的斷言層級錯了」。**

要抓這類 bug，測試必須驗：

| 錯誤的斷言 | 正確的斷言 |
|---|---|
| `cameraMode === GodView` | `world.getActiveCamera() !== pawnCamera` |
| `undoStack.undoCount === 0` | undo 後 `chunk.rebuilds` 增加 |
| `ui.tabs !== null` | 點擊分頁後 `applyPreset` 被呼叫 |

## 七、結論

**外部審查的 8 項全部屬實，判斷準確。** 它正確指出「功能已建立但未接入完整遊戲流程」是主要缺陷。

**最重要的判斷**：這不是重做，是補接線。而且缺得很集中——`MyGameMode.ts` 一個檔案就涵蓋 8 項。

**下一步**：按第一梯隊 → 第二梯隊 → 第三梯隊的順序修正，每修一項就補一個「驗行為而非驗存在」的測試。
