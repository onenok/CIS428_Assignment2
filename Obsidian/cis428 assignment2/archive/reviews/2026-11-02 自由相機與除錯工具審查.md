## 問題 1：FreeCamera 未支援按鍵重綁定

**嚴重度：中**
**查證結果：✅ 屬實**

### 現況

`MyGameMode.ts` 的 `readAxis()` 使用硬編碼字串：

```ts
forward: this.readAxis(controller, 'KeyW', 'KeyS'),
right: this.readAxis(controller, 'KeyD', 'KeyA'),
up: this.readAxis(controller, 'Space', 'ControlLeft'),
```

### 問題

1. **違反專案慣例** —— `keyBindings.ts` 檔頭明寫：

   > Gameplay code must read from `KeyBindings` — never compare against a literal `'KeyX'` string.

2. **`ControlRight` 遺漏** —— `DEFAULT_KEY_BINDINGS.flyDown` 是 `['ControlLeft', 'ControlRight']`，但自由相機只認 `ControlLeft`。

3. **重綁定無效** —— 使用者若把移動鍵改成 ESDF，自由相機仍用 WASD。

### 審查建議的可行性

審查建議「透過現有 `KeyBindings` 表取得所有 movement action 的按鍵」。

**但這做不到** —— `KeyBindings` 表裡**沒有** `moveForward` / `moveBack` / `moveLeft` / `moveRight`。這些是引擎 `DefaultPlayerController` 自己的內部綁定，我們的表從未涵蓋。

### 修正方案

在 `keyBindings.ts` 新增 6 個 action：

```ts
readonly moveForward: KeyBinding;   // ['KeyW']
readonly moveBack: KeyBinding;      // ['KeyS']
readonly moveLeft: KeyBinding;      // ['KeyA']
readonly moveRight: KeyBinding;     // ['KeyD']
readonly moveUp: KeyBinding;        // ['Space']
readonly moveDown: KeyBinding;      // ['ControlLeft', 'ControlRight']
```

`readAxis` 改為接受 `keyof KeyBindingTable`，內部用 `KeyBindings[action]` 逐一檢查 `isKeyDown`。

**注意**：這些新 action **不會**被 `MyPlayerController.handleKeyDown` 攔截（它們不是 `GameplayAction`），只是給自由相機讀取用。引擎的 `DefaultPlayerController` 仍會處理 WASD 移動，兩者並存不衝突 —— 因為自由相機啟用時 `isFreeLookEnabled` 只吞滑鼠，不吞鍵盤。

## 問題 2：啟用 FreeCamera 時遺失目前 pitch

**嚴重度：中**
**查證結果：✅ 屬實**

### 現況

`MyGameMode.toggleFreeCamera()`：

```ts
const rotation = pawn.getWorldRotation();
this.freeCamera.activate(position, rotation.y, rotation.x);
```

### 問題

`CharacterPawn.updateCamera()`（`CharacterPawn.ts:267-296`）把 pitch 寫進 **`cameraPivot.rotation.x`**：

```ts
const pitchingNode = this.cameraPivot;
// ...
pitchingNode.addLocalRotation(MathHelpers.makeRotation({ pitch: newPitch - currentPitch }));
```

**pawn root 的 `rotation.x` 永遠是 0** —— yaw 由 movement node 寫進 root，pitch 由 `updateCamera` 寫進 pivot。

所以 `rotation.x` 永遠拿到 `0` → 自由相機一定從水平視角開始。

### 修正方案

`MyCharacterPawn` 加 public getter：

```ts
/** Current camera pitch in radians, read from the pivot that owns it. */
public getCameraPitch(): number {
  return this.cameraPivot?.rotation.x ?? 0;
}
```

`toggleFreeCamera` 改用 `pawn.getCameraPitch()`。

**注意**：`cameraPivot` 是 `protected`，但 `MyCharacterPawn` 是 `CharacterPawn` 的子類，可以直接存取。

## 問題 3：視窗失焦可能造成按鍵狀態卡住

**嚴重度：中**
**查證結果：✅ 屬實（且是既有 bug，非本輪引入）**

### 現況

`MyPlayerController` 有三個 held state：

| 欄位 | 引入時間 | 清除時機 |
|---|---|---|
| `isFlyUpHeld` | 既有 | `handleKeyUp` |
| `isFlyDownHeld` | 既有 | `handleKeyUp` |
| `isDebugModifierHeld` | **本輪新增** | `handleKeyUp` |

### 問題

`InputManager` 註冊的事件（`InputManager.ts:695-726`）：

```
keydown / keyup
mousedown / mouseup / mousemove / click / wheel
touchstart / touchmove / touchend / touchcancel
pointerlockchange / pointerlockerror（含 moz/webkit 前綴）
gamepadconnected / gamepaddisconnected
```

**沒有 `blur`，也沒有 `visibilitychange`。**

所以按住按鍵後切換視窗（Alt+Tab、點其他視窗），瀏覽器不再送 `keyup`：

- `isDebugModifierHeld` 卡在 `true` → 之後按 B/C 都會被當成 F3 chord
- `isFlyUpHeld` 卡在 `true` → 飛行時持續上升
- `isFlyDownHeld` 卡在 `true` → 持續下降

**這是既有 bug** —— `isFlyUpHeld` / `isFlyDownHeld` 從飛行功能實作時就存在，只是沒人發現。

### 修正方案

`MyPlayerController` 在 `beginPlay` 時註冊 `window.blur` 監聽，`endPlay` 時移除：

```ts
private readonly handleWindowBlur = (): void => {
  this.isFlyUpHeld = false;
  this.isFlyDownHeld = false;
  this.isDebugModifierHeld = false;
  this.lastToggleFlightPressMs = -Infinity;
};
```

同時清除 `lastToggleFlightPressMs`，避免失焦後回來的第一下被誤判為 double-tap。

## 修正實作記錄

### 問題 3：視窗失焦卡鍵

`MyPlayerController` 新增：

```ts
private readonly handleWindowBlur = (): void => {
  this.isFlyUpHeld = false;
  this.isFlyDownHeld = false;
  this.isDebugModifierHeld = false;
  this.lastToggleFlightPressMs = -Infinity;
};

public override beginPlay(): boolean {
  if (!super.beginPlay()) return false;
  // Headless test worlds have no `window`; the blur guard is a browser-only concern.
  if (typeof window !== 'undefined') {
    window.addEventListener('blur', this.handleWindowBlur);
  }
  return true;
}

public override endPlay(): boolean {
  if (typeof window !== 'undefined') {
    window.removeEventListener('blur', this.handleWindowBlur);
  }
  this.handleWindowBlur();
  return super.endPlay();
}
```

```ts
function readAxis(
  input: ENGINE.InputManager | null | undefined,
  positive: keyof KeyBindingTable,
  negative: keyof KeyBindingTable,
): number {
  if (!input) return 0;
  const isHeld = (action: keyof KeyBindingTable): boolean =>
    KeyBindings[action].some(code => input.isKeyDown(code));
  return (isHeld(positive) ? 1 : 0) - (isHeld(negative) ? 1 : 0);
}
```

### 問題 4：碰撞 offset 錯誤（根因確認）

查 Rapier 型別定義 `geometry/collider.d.ts`：

```
static voxels(voxels: Float32Array | Int32Array, voxelSize: Vector): ColliderDesc;
```

> @param data - Defines the set of voxels. If this is a `Int32Array` then
>               each voxel is defined from its **(signed) grid coordinates**,
>               with 3 (contiguous) integers per voxel in 3D.

**Rapier 的 voxel `(x, y, z)` 佔 `[x * voxelSize, (x + 1) * voxelSize)`。**

我們的 voxel 資料語意完全相同 —— grid `(0,0,0)` 佔 local `[0, 1)`。

所以 `offset` 應該是 **`0`（不設定）**，不是 `0.5`。

原本的 `offset: (0.5, 0.5, 0.5)` 把整個碰撞網格往 **+X / +Y / +Z 各推半格**，導致：

- 玩家站在地面上時 Y = `12.410` 而非 `11.9`（高 0.51）
- F3+B 線框與方塊錯開半格

**修正**：移除 `offset` 欄位。

### 問題 5：自由相機模式下角色仍移動

**根因**：`DefaultPlayerController.handleKeyDown()` 在 `MyPlayerController` 呼叫 `super.handleKeyDown(e)` 時，會把 WASD 寫進 `this.forward` / `this.backward` / `this.left` / `this.right`，然後 `tickPrePhysics()` 用這些值驅動 pawn。

自由相機只吞了滑鼠（`handleMouseMove`），沒吞鍵盤 —— 所以 WASD 同時驅動相機和角色。

**修正**：`MyPlayerController.handleKeyDown` / `handleKeyUp` 開頭加入：

```ts
if (this.isFreeLookEnabled && this.isFreeCameraAxis(e.code)) {
  return true;
}
```

`isFreeCameraAxis()` 從 `KeyBindings` 讀取 6 個 `freeCamera*` action 的綁定，所以重綁定後仍然有效。
