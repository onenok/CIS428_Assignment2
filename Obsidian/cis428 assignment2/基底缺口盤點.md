| 檔案                                    | 內容                                                                                                                                                                                  |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/character/MyCharacterPawn.ts`    | 繼承 `DefaultCharacterPawn`，覆寫 `getInitialCameraPositions()` 讓 pivot 與 camera 重合（第一人稱，不建 spring arm），並覆寫 `createMovementNode()` 換成 `FlyingMovementNode` |

**關鍵設計：為什麼繼承 `DefaultCharacterPawn` 而不是 `CharacterPawn`**

`DefaultCharacterPawn` 已內建 7 個委派（`onKeyDown` / `onKeyUp` / `onMouseDown` / `onMouseUp` / 3 個 gamepad），
`DefaultPlayerController` 會自動轉發給它們。繼承它就不用自己重建這套轉發鏈。

**關鍵設計：為什麼按鍵全部走 `KeyBindings`**

使用者明確要求「按鍵必須用變數，不可 hard code，預留自訂功能」。
所有比較都走 `matchesBinding(action, e)`，遊戲邏輯裡**零個** `'KeyX'` 字面值。

**關鍵設計：`E` 鍵衝突**

引擎的 `DefaultPlayerController` 把 `KeyE` 綁到 interact。我們的 `openPalette` 也用 `KeyE`，
但 `MyPlayerController.handleKeyDown()` 在呼叫 `super.handleKeyDown()` **之前**就攔截並回傳 `true`，
所以建造模式下 `E` 開背包，interact 永遠不會觸發。

**驗證**：`tests/input/keyBindings.unit.ts`（18 個）+ `tests/character/playerStack.engine.ts` 的「MyPlayerController: action routing」6 個

### B3. `MovementMode` 沒有 `Flying` ✅ 已解決

**修復內容**

`src/character/FlyingMovementNode.ts` 繼承 `CharacterMovementNode`（**不是** `BasePawnMovementNode`）。

**關鍵設計：為什麼繼承 `CharacterMovementNode`**

`CharacterMovementNode` 已經有完整的物理角色控制器：

- `physicsEngine.computeCharacterMovement()` 做碰撞解析
- `isGrounded` 落地偵測
- `verticalVelocity` + 重力
- `captureMovementState()` / `restoreMovementState()` 網路同步

飛行只需要**取代垂直運動**，水平移動、碰撞、落地偵測全部繼承。

**關鍵設計：為什麼不加 `MovementMode.Flying`**

`MovementMode` 是引擎 enum，加值會影響所有讀 `getMovementMode()` 的引擎程式碼。
改用獨立的 `isFlying: boolean`，引擎消費者完全不受影響。

**關鍵設計：落地自動取消**

`performMovementStep()` 在飛行分支裡仍呼叫 `computeCharacterMovement()`，
拿到 `isGrounded` 後若為 `true` 且正在下降，就 `setFlying(false)`。

**驗證**：`tests/character/playerStack.engine.ts` 的「FlyingMovementNode: flight state」5 個測試
（上升、下降、懸停不墜落、切換旗標、關閉時清垂直速度）

**修法（已實施）**

把測試檔從 `src/**/__tests__/` 搬到專案根的 `tests/`：

```

├── build/
│   ├── buildMode.runtime.md
│   └── raycast.engine.ts
├── voxel/
│   ├── VoxelMeshNode.engine.ts
│   ├── coords.unit.ts
│   ├── faceCulling.unit.ts
│   └── greedyMesh.unit.ts
└── world/
    ├── World.engine.ts
    ├── headlessWorld.ts
    └── smoke.engine.ts
```

配套修改：

1. `scripts/verify/run.ts`：`SRC_ROOT` → `TESTS_ROOT`（掃描 `tests/`）
2. `tsconfig.json`：`include` 加入 `tests/**/*`
3. 各測試檔的相對 import 路徑（`../../../scripts/verify/` → `../../scripts/verify/`、`../mesher.js` → `../../src/voxel/mesher.js` 等）
