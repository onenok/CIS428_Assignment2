# 引擎禁止用法

> 整理自 `AGENTS.md`、`.cursor/rules/genesys-mcp.mdc`、`.agents/skills/*`。
> 這些是**引擎官方明文禁止**的做法，不是風格偏好。

---

## 一、指令與驗證

| 禁止 | 原因 | 正確做法 |
|---|---|---|
| `pnpm test` | 專案沒有測試框架，指令不存在 | 用 `pnpm verify`（我們自建） |
| `pnpm dev` | 不支援 | 用 TSB Studio 的 play mode |
| `pnpm start` | 不支援 | 同上 |
| 只跑 `pnpm verify` 不跑 `pnpm build` | `tsx` 不做型別檢查 | 兩者都要跑 |

**允許的驗證指令只有兩個**：`pnpm build`（編譯）與 `pnpm lint`（檢查 + 自動修）。

---

## 二、類別註冊

| 禁止 | 正確做法 |
|---|---|
| `@ENGINE.EngineClass()` | `@ENGINE.GameClass()` |
| 手動編輯 `auto-imports.ts` | 由 build pipeline 自動生成，改了會被覆寫 |
| 手動編輯 `game-data.ts` | 同上 |

`EngineClass` 是引擎內部用的。自訂類別一律 `GameClass`。

---

## 三、節點建立與生命週期

| 禁止 | 正確做法 |
|---|---|
| `new MyNode(...)` | `MyNode.create(options)` |
| `world.remove(node)` 當作刪除 | `node.destroy()` |
| `world.removeActor(node)` | `node.destroy()`（已 deprecated，lint 會報錯） |
| `world.disposeSubtreeResources(node)` | `node.destroy({ forceDispose: true })` |
| 手動 splice `parent.children` | `parent.insert(child, index)` |
| 在 `beginPlay` 裡改場景視覺 | 用 MCP 改場景，或改類別預設值 |
| 重設 play state 後重新 add | `Ended` 是終態，要建新實例 |

### `remove()` vs `destroy()` 的差別（v16 起）

| 意圖 | API | 跑 `endPlay`？ | 釋放 GPU？ |
|---|---|---|---|
| 換父節點 / 暫時脫離 | `remove()` / `removeFromParent()` | ❌ | ❌ |
| 永久刪除 | `destroy()` | ✅ | 播放中會 |

**這是靜默破壞**：用 `remove()` 刪節點不會報錯，但節點會繼續 tick、GPU 記憶體會漏。

## 四、渲染

| 禁止 | 正確做法 |
|---|---|
| `renderer.render(world)` | `super.tick(t)`，渲染自動發生 |
| `world.renderScene()` | 同上 |
| 直接寫 `THREE.Scene.background` | 實作 `ENGINE.ISceneEnvironmentSource` |
| `new THREE.Mesh(...)` 後再 `geometry.dispose()` | `destroy()` 已經釋放了，重複釋放會出錯 |

---

## 五、資產路徑

| 禁止 | 正確做法 |
|---|---|
| 相對路徑 `./assets/foo.png` | `@project/assets/foo.png` |
| 程式化拼接路徑 | 寫死完整路徑 |
| `@packs/<name>/assets/...` 當 runtime URL | `@packs/` 只能用在 TS import |
| 解析後用 `TextureLoader` | `ENGINE.resourceManager.loadTexture(ENGINE.AssetPath.fromString(...))` |
| 在 raw HTML 直接用 `@project/` | 先 `ENGINE.resolveAssetPathsInText(html)` |

`TextureLoader` 只能用於**外部 URL**。專案資產會被 bake 成 `.ktx2`，`TextureLoader` 讀不到。

## 六、UI

| 禁止 | 正確做法 |
|---|---|
| 把 HTML 加到 `document.body` | 加到 `world.gameContainer` |
| `element.innerHTML = 玩家字串` | `element.textContent = 玩家字串` |
| `setHTML()` / `iconHtml` / `imageHtml` 傳玩家字串 | 只傳開發者自己寫的 markup |
| `customStyles` 傳網路字串 | 只傳開發者控制的值 |
| 手刻 HTML/CSS 做 HUD | 優先用 `BaseUIComponent` 元件庫 |

### Safe UI 三條鐵律

1. 動態／網路字串 → `setLabel` / `setMessage` / `setTitle` / `textContent`
2. 圖示／富文本 → `ENGINE.Icons.*` 或自己寫的靜態 SVG
3. 玩家字串**絕不**進 `*Html`、`setHTML`、`innerHTML`、`customStyles`

`customStyles` 還有 allowlist：`position`、`z-index`、`inset`、`pointer-events`、`transform` 全部被封鎖。

## 七、場景檔案

| 禁止 | 正確做法 |
|---|---|
| 讀／開 `*.genesys-scene` | 用 MCP `query_node` |
| 手改 `.prefab.json` | 用 MCP `action_prefab` |
| 用 shell / curl 打 MCP HTTP endpoint | 只用 MCP 工具 |

`*.genesys-scene` 檔案很大，而且**編輯器才是唯一真相**。直接改檔案會被編輯器覆寫。

## 八、已移除的舊 API（v18 專案）

| 已移除 | 替代 |
|---|---|
| `World.getPhysicsEngine()` | `world.gameLoop.physicsEngine` |
| `World.getNavigationServer()` | `world.gameLoop.navigationServer` |
| `World.createPhysicsEngine()` | `gameLoop.ensurePhysicsEngine(world)` |
| `getRootScene()` | `rootScene`（屬性） |
| `getPhysicsEngine()` | `physicsEngine`（屬性） |
| `getPostProcessManager()` | `postProcessManager`（屬性） |
| `setActiveScenePath(p)` | `activeScenePath = p` |
| `fog.setFogMode(...)` 鏈式 | `fog.fogMode = ...` |
| `Actor` / `rootComponent` / `sceneComponents` | `SceneNode` / `children` |
| `getActor()` / `getComponent()` | `getRoot()` / `getNode()` |
| `getActors*` | `getNodes*` |
| `doBeginPlay` / `doEndPlay` | `beginPlay()` / `endPlay()` |
| `addForwardInput` | `moveForward` |
| `beginFire` | `fire` |
| `instanceScale` / `instanceOffset` | `baseScale` / `baseOffset` |
| `virtualJoystickOptions.hidden` | `virtualJoystickOptions.enabled: false` |
| `*.anim.json` | `*.animconfig.json` |
| `'genesys.js'` / `'@directivegames/genesys.js'` | `'@gnsx/genesys.js'` |

**注意**：專案 lint 把 `@typescript-eslint/no-deprecated` 設為 **error**。用到任何 deprecated API，`pnpm lint` 會直接失敗。

## 九、程式碼風格

| 禁止 | 正確做法 |
|---|---|
| 單體式大檔案 | 拆成模組化元件 |
| `as any` | 明確型別 |
| 自己重造引擎已有的輪子 | 先搜引擎原始碼 |
| 未經要求就寫文件／測試範例 | 先問 |

---

## 十、與我們專案的衝突

| 引擎規定 | 我們的狀況 | 處理 |
|---|---|---|
| 「不要寫測試」 | 使用者明確要求三層測試 | 使用者要求優先，已建立 `pnpm verify` |
| 「不要寫文件」 | 使用者明確要求 Obsidian 計劃 | 同上 |
| 「`pnpm test` 不支援」 | 我們用 `pnpm verify` | 不衝突 |

**原則**：引擎規定是預設值，使用者明確要求時以使用者為準。但**技術性禁止**（如 `pnpm test` 不存在）不可違反。
