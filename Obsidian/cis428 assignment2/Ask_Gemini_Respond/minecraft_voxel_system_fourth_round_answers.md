# Minecraft Voxel & Collision System - Fourth Round Solutions (TSB Studio / Three.js / Rapier)

這份文件針對你在第四輪提出的邊界情況（問題 16 至 20）以及 Amanatides & Woo DDA 主迴圈的實作細節給出最後的確認與最佳實踐建議。

### 問題 16：`tMin` 初始化為 `0` 會漏掉「貼著方塊表面」的命中

* **結論**：**你的推論與修改完全正確。**
* **解析**：如果射線起點剛好貼在方塊表面上（例如精確對齊或小數點極限狀況），初始化 `tMin = 0` 會讓 `t1 > tMin`（`0 > 0`）失效，導致漏掉邊界命中。改成 `tMin = -Infinity` 並在最後檢查 `tMin < 0`（代表起點在 box 內或朝外）是更嚴謹且標準的做法。

### 問題 17：`Math.sign(0)` 回傳 `0`，法向量會變成零向量，是否需要防禦？

* **結論**：**理論上不會發生，但加上簡單防禦可以確保萬無一失。**
* **解析**：因為 `hitAxis` 僅在 `Math.abs(d) >= 1e-8` 時被選中，`dir[hitAxis]` 絕對不為 0。不過為了保險，防禦性寫法可以寫成：`normal[axis] = -Math.sign(dir[axis]) || -1;` 或直接依賴邏輯前提。

### 問題 18：`placementCell` 可能超出世界邊界，是否該在 `checkPlacement()` 處理？

* **結論**：**你的理解完全正確。**
* **解析**：`placementCell` 僅負責純粹的數學座標位移（`cell + normal`）。世界的邊界檢查與合法性驗證應該統一交給 `checkPlacement()` / `isWithinBuildBounds()` 去擋，這樣能維持模組職責單一。

### 問題 19：`VoxelRaycastHit.distance` 的用途？

* **結論**：**你的理解完全正確。**
* **解析**：DDA 走訪順序本身就保證了「第一個檢測到碰撞的格子就是距離最近的」。`distance` 欄位純粹是資訊性（Informational）用途，可用於 UI 顯示準心距離、粒子特效生成位置或除錯日誌。

### 問題 20：`VoxelShape.boxCount` 是否該在 constructor 預先算好？

* **結論**：**非常值得的微優化。**
* **解析**：雖然 V8 有內嵌快取與優化，但在每幀或複雜方塊的 hot loop 中，直接讀取快取的 `readonly boxCount` 屬性比每次都做 `length / 6` 運算更乾淨、明確且有效率。
