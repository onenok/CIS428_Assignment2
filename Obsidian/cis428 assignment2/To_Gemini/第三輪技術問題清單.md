## 問題 10：`getHitNormal()` 的 `else if` 鏈在角落命中時會出錯

**你的寫法**：

```ts
function getHitNormal(point: Vector3, box: Float32Array): Vector3 {
    const EPS = 1e-4;
    const [minX, minY, minZ, maxX, maxY, maxZ] = box;
    const normal = new Vector3(0, 0, 0);

    if (Math.abs(point.x - minX) < EPS) normal.set(-1, 0, 0);
    else if (Math.abs(point.x - maxX) < EPS) normal.set(1, 0, 0);
    else if (Math.abs(point.y - minY) < EPS) normal.set(0, -1, 0);
    else if (Math.abs(point.y - maxY) < EPS) normal.set(0, 1, 0);
    else if (Math.abs(point.z - minZ) < EPS) normal.set(0, 0, -1);
    else if (Math.abs(point.z - maxZ) < EPS) normal.set(0, 0, 1);

    return normal;
}
```

**問題**：

射線斜射進方塊角落時，命中點可能同時貼近兩個面（例如 `maxX` 和 `maxY`）。`else if` 鏈只會回傳第一個匹配的軸（`+X`），但實際上射線可能更接近 `+Y` 面。

**具體情境**：

- 方塊 `[0,0,0]` 到 `[1,1,1]`
- 射線從 `(2, 2, 0.5)` 朝 `(-1, -1, 0)` 方向
- 命中點在 `(1, 1, 0.5)` —— 同時貼近 `maxX` 和 `maxY`
- 你的程式碼回傳 `(1, 0, 0)`（`+X`）
- 但射線是 45° 斜射，`+X` 和 `+Y` 機率相等
- **如果玩家想放在頂面，會放到側面**

**我的理解**：應該用「射線方向」判斷，而不是「命中點貼近哪個面」。或者在 AABB slab 測試時就記錄「哪個軸的 `tNear` 最大」（即最後進入的軸）。

```ts
// slab method 記錄最後進入的軸
let tMin = 0;
let hitAxis = -1;
for (let axis = 0; axis < 3; axis++) {
  const t1 = (box[axis] - origin[axis]) * invD[axis];
  const t2 = (box[axis + 3] - origin[axis]) * invD[axis];
  const tNear = Math.min(t1, t2);
  if (tNear > tMin) {
    tMin = tNear;
    hitAxis = axis;
  }
}
// hitAxis 就是法向量的軸，方向由 dir[hitAxis] 的正負決定
normal[hitAxis] = -Math.sign(dir[hitAxis]);
```

**請確認**：Minecraft 是怎麼算 `hitNormal` 的？有沒有更穩健的做法？

const startX = Math.floor(origin.x);

## 問題 12：`testRayAgainstShape()` 的實作細節

你提到「對該格子的所有 AABB 進行精確測試」，但沒給實作。

**我的理解**：用 slab method：

```ts
function rayAabb(
  origin: readonly [number, number, number],
  dir: readonly [number, number, number],
  box: Float32Array,
  boxOffset: number,
  maxT: number,
): { t: number; axis: number } | null {
  let tMin = 0;
  let tMax = maxT;
  let hitAxis = -1;

  for (let axis = 0; axis < 3; axis++) {
    const d = dir[axis];
    const o = origin[axis];
    const lo = box[boxOffset + axis];
    const hi = box[boxOffset + axis + 3];

    if (Math.abs(d) < 1e-8) {
      // 射線平行於這個軸
      if (o < lo || o > hi) return null;
      continue;
    }

    const invD = 1 / d;
    let t1 = (lo - o) * invD;
    let t2 = (hi - o) * invD;
    if (t1 > t2) { const tmp = t1; t1 = t2; t2 = tmp; }

    if (t1 > tMin) { tMin = t1; hitAxis = axis; }
    if (t2 < tMax) tMax = t2;
    if (tMin > tMax) return null;
  }

  if (hitAxis < 0) return null;   // 起點在 box 內
  return { t: tMin, axis: hitAxis };
}
```

**請確認**：

1. 這個實作是否正確？
2. `hitAxis` 是否就是 `hitNormal` 的軸？
3. `hitAxis < 0` 代表「起點在 box 內」，這個判斷是否正確？

## 補充：我發現的第二輪實作問題

### 問題 6 的連帶影響

你確認了 `placementCell` 應該用「命中格子 + 法向量」。這意味著 **`HitLike` 型別必須增加 `cell` 欄位**：

```ts
// 現況（src/build/placement.ts）
export interface HitLike {
  readonly hitLocation: { readonly x: number; readonly y: number; readonly z: number };
  readonly hitNormal: { readonly x: number; readonly y: number; readonly z: number };
}

// 必須改成
export interface HitLike {
  readonly cell: VoxelCell;              // ← 新增：命中的格子座標
  readonly hitLocation: { readonly x: number; readonly y: number; readonly z: number };
  readonly hitNormal: { readonly x: number; readonly y: number; readonly z: number };
}
```

而 `BuildController.raycastFromCamera()` 目前回傳 `ENGINE.PhysicsQueryHit`，**沒有 `cell` 欄位**。所以：

- 階段 5（DDA raycast）必須回傳自訂的 `VoxelRaycastHit`，不是 `PhysicsQueryHit`
- 這會影響 `BuildController` 的所有呼叫點

**請確認**：這個推論是否正確？有沒有更平滑的遷移方式？
