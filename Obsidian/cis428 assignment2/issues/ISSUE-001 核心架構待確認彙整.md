## Q1. 地表高度 `surfaceY` 定在 0 還是其他值？

**影響**：整個世界生成的基準面、玩家出生高度、相機初始位置。

| 選項                 | 說明                           |
| -------------------- | ------------------------------ |
| A. `surfaceY = 0`  | 最直覺，方塊頂面在 Y=0         |
| B. `surfaceY = 64` | Minecraft 慣例（海平面 62/63） |
| C. 其他              |                                |

**我的建議**：**A（`surfaceY = 0`）** —— 這是小場景，不需要 Minecraft 的座標尺度。玩家出生在 `Y = 1.8`（角色高度）。

---

## Q2. 要不要有地形起伏（Perlin noise）？

**影響**：世界生成演算法、可編輯區塊的初始狀態、玩家移動體驗。

| 選項        | 說明                 | 代價                |
| ----------- | -------------------- | ------------------- |
| A. 完全平坦 | 可編輯區塊是空的平地 | 最簡單，但單調      |
| B. 輕微起伏 | 高度差 ±2 格        | 中等，需 noise 實作 |
| C. 明顯起伏 | 高度差 ±8 格        | 好看但影響建造體驗  |

**我的建議**：**A（完全平坦）** —— 這是**建造遊戲**，玩家要放方塊。起伏地形會讓放置變麻煩（要對齊高度）。平坦地面最適合建造。

> 若之後覺得單調，可加「裝飾性起伏」在**不可編輯區塊**（周圍 4 圈平面），不影響建造。

## Q3. 周圍一圈要不要只生成表面（省效能）？

**影響**：世界生成的資料量、記憶體、渲染批次。

**這題其實已經定案了** —— 你之前說：

> 只有可編輯區域是完整區塊 chunk
> 從可編輯區域向外延伸額外四個區塊範圍都是只有一層頂層的平面
> 超過的 is LOD, fog or something like that

所以答案是 **「是，只生成表面」**。這題可以關閉。

## Q4. 對話框位置（底部／中央）？

**影響**：UI 佈局骨架、與其他 UI（快捷欄、調色盤）的衝突。

| 選項        | 說明                        | 衝突風險                 |
| ----------- | --------------------------- | ------------------------ |
| A. 底部     | 像視覺小說 / Minecraft 字幕 | 與快捷欄（底部中央）衝突 |
| B. 中央偏下 | 像 RPG                      | 較安全                   |
| C. 中央     | 像過場動畫                  | 遮擋視線                 |

**我的建議**：**B（中央偏下）** —— 你之前說 N2 對話在底部，但底部中央要放快捷欄。折衷：對話框在**底部但偏上**（距底部約 120px），快捷欄在最底。

**我的建議**：**底部中央**，`InventoryBar` 預設位置。與 Q4 的對話框錯開。

## Q6. 玩家角色用內建 mannequin 還是自製？

**影響**：資產製作工作量、第一人稱是否看得到手。

| 選項                     | 說明                       | 代價                 |
| ------------------------ | -------------------------- | -------------------- |
| A. 內建 mannequin        | 引擎自帶，有 8 個動畫 clip | 0 工作量，但外觀普通 |
| B. 自製 voxel 角色       | 用 VoxEdit 做              | 需建模 + 綁骨 + 動畫 |
| C. 內建 mannequin 先頂著 | Demo 用 A，最後換 B        | 推薦                 |

**我的建議**：**C** —— Demo 階段用內建 mannequin（`mannequinG.glb` 已有 Idle/Run/Walk/Jump），最後有時間再換。

> 第一人稱時看不到自己，所以外觀影響很小。

## Q8. 透明方塊（水、玻璃）何時實作？

**影響**：材質系統、渲染排序（透明物件要後渲染）。

| 選項           | 說明                                                        |
| -------------- | ----------------------------------------------------------- |
| A. 第一版就做  | 需處理 `transparent: true` + `depthWrite: false` + 排序 |
| B. Demo 後再做 | 先用不透明方塊                                              |
| C. 不做        | 9 種材質全部不透明                                          |

**我的建議**：**B** —— 透明方塊會讓 mesher 複雜度上升（要分兩個 mesh：不透明 + 透明）。第一版先全部不透明，架構上預留 `isTransparent` 旗標。

---

## Q9. 調色盤要不要分頁（9 種以上時）？

**影響**：UI 元件選擇（`InventoryBar` vs `InventoryGrid`）。

**我的建議**：**9 種用 `InventoryBar`（單排 9 格）**，超過 9 種再改 `InventoryGrid` + 分頁。第一版 9 種不需要分頁。
