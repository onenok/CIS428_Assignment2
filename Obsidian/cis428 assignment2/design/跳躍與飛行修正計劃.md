# 跳躍與 flyDown 修正計劃

> 相關：[[方塊系統實作規格書]]、[[上帝視角相機設計]]

## 問題陳述

兩個獨立的輸入 bug，都源自 `matchesBinding()` 與 `MyPlayerController.handleKeyDown()` 的設計缺陷：

| # | 症狀 | 影響 |
|---|---|---|
| 1 | 按 Ctrl 無法下降（飛行時） | `flyDown` 永遠不觸發 |
| 2 | 按 Space 無法跳躍（地面時） | 跳躍完全失效 |

## 根因分析

### Bug 1：`flyDown` 永遠不觸發

`flyDown` 綁定 `ControlLeft` / `ControlRight`。按 Ctrl 時：

```typescript
// keyBindings.ts:136-149
export function matchesBinding(action, e): boolean {
  if (!isBound(action, e.code)) return false;        // ✅ 'ControlLeft' 有綁定
  const wantsModifier = MODIFIER_ACTIONS.has(action); // ❌ flyDown 不在集合 → false
  const hasModifier = Boolean(e.ctrlKey) || Boolean(e.metaKey); // ✅ 按 Ctrl → true
  if (wantsModifier !== hasModifier) return false;   // ❌ false !== true → 回傳 false
  return !e.altKey;
}
```

**`matchesBinding` 假設「不在 `MODIFIER_ACTIONS` 的動作都不該帶 Ctrl」**，但 `flyDown` 的綁定鍵**本身就是 Ctrl**。這是設計缺陷，不是設定錯誤。

`MODIFIER_ACTIONS` 目前只有：

```typescript
const MODIFIER_ACTIONS: ReadonlySet<keyof KeyBindingTable> = new Set([
  'undo', 'redo', 'submitDesign',
]);
```

### Bug 2：跳躍完全失效

`toggleFlight` 綁 `Space`，引擎的 `jumpKeys` 也是 `Space`。

`MyPlayerController.handleKeyDown` 在 `matchesBinding('toggleFlight', e)` 時**無條件 `return true`**：

```typescript
// MyPlayerController.ts:216-228
if (matchesBinding('toggleFlight', e)) {
  const now = performance.now();
  if (now - this.lastToggleFlightPressMs <= DOUBLE_TAP_WINDOW_MS) {
    this.lastToggleFlightPressMs = -Infinity;
    this.onAction.invoke('toggleFlight');
    return true;              // 雙擊：吞掉（正確）
  }
  this.lastToggleFlightPressMs = now;
  this.isFlyUpHeld = true;
  return true;                // ❌ 單擊也吞掉 → super.handleKeyDown 收不到 Space
}
```

`DefaultPlayerController.handleKeyDown` 的跳躍邏輯（`DefaultPlayerController.js:271-282`）：

```javascript
else if (this.jumpKeys.includes(key)) {
  if (this.pawn instanceof MovementPawn) {
    if (this.pawn.isLocalAutonomousProxy()) {
      this.jumpPressedThisFrame = true;   // ← 永遠不會被設定
    } else {
      this.pawn.jump();
    }
    return true;
  }
}
```

因為 `MyPlayerController` 先 `return true`，`super.handleKeyDown(e)` 從未被呼叫 → `jump<|place_holder_mm_span_0442|>PressedThisFrame` 永遠是 `false` → 跳躍失效。

## 修正方案

### 修正 1：`matchesBinding` 支援「綁定鍵本身就是修飾鍵」

**檔案**：`src/input/keyBindings.ts`

新增修飾鍵 code 集合，並在修飾鍵檢查**之前**短路：

```typescript
/**
 * Key codes that ARE modifier keys.
 *
 * Pressing one of these sets the matching `ctrlKey` / `shiftKey` / `altKey` /
 * `metaKey` flag on the event. A binding whose own key is a modifier (e.g.
 * `flyDown = Ctrl`) must not be rejected by the modifier check, or it could
 * never fire — the flag it sets is exactly what the check rejects.
 */
const MODIFIER_CODES: ReadonlySet<string> = new Set([
  'ControlLeft', 'ControlRight',
  'ShiftLeft', 'ShiftRight',
  'AltLeft', 'AltRight',
  'MetaLeft', 'MetaRight',
]);

export function matchesBinding(
  action: keyof KeyBindingTable,
  e: Pick<KeyboardEvent, 'code' | 'ctrlKey' | 'metaKey' | 'altKey'>,
): boolean {
  if (!isBound(action, e.code)) {
    return false;
  }
  // A modifier key bound directly to an action is its own chord: the flag it
  // sets would otherwise make every such binding look like an unwanted chord.
  if (MODIFIER_CODES.has(e.code)) {
    return true;
  }
  const wantsModifier = MODIFIER_ACTIONS.has(action);
  const hasModifier = Boolean(e.ctrlKey) || Boolean(e.metaKey);
  if (wantsModifier !== hasModifier) {
    return false;
  }
  return !e.altKey;
}
```

**為什麼安全**：

| 動作 | 綁定 | 按鍵 | `MODIFIER_CODES.has` | 結果 |
|---|---|---|---|---|
| `flyDown` | `ControlLeft` | Ctrl | ✅ | `true`（修正） |
| `undo` | `KeyZ` | Ctrl+Z | ❌ | 走原邏輯 → `true` |
| `undo` | `KeyZ` | Z | ❌ | 走原邏輯 → `false` |
| `toggleBuildMode` | `KeyB` | Ctrl+B | ❌ | 走原邏輯 → `false` |

只有「綁定鍵本身是修飾鍵」的動作受影響，其餘完全不變。

### 修正 2：`Space` 只在飛行時吞掉

**檔案**：`src/character/MyPlayerController.ts`

新增欄位（由 `MyGameMode` 同步）：

```typescript
/**
 * True while the pawn is flying.
 *
 * Mirrored from `MyGameMode.isFlying` rather than read from the pawn: the
 * controller must not import `MyCharacterPawn` (it would create a cycle
 * through the game mode), and the game mode already owns the authoritative
 * flag.
 */
public isFlying: boolean = false;
```

改寫 `toggleFlight` 分支：

```typescript
if (matchesBinding('toggleFlight', e)) {
  const now = performance.now();
  if (now - this.lastToggleFlightPressMs <= DOUBLE_TAP_WINDOW_MS) {
    this.lastToggleFlightPressMs = -Infinity;
    this.onAction.invoke('toggleFlight');
    return true;   // Double-tap: swallow, never jump.
  }
  this.lastToggleFlightPressMs = now;
  this.isFlyUpHeld = true;
  // While flying, Space means "ascend" and must not also jump. On the ground
  // it means "jump", so let it fall through to the engine's jump handling.
  return this.isFlying;
}
```

**為什麼 `return this.isFlying` 正確**：

| 狀態 | `isFlying` | 回傳 | `super.handleKeyDown` | 結果 |
|---|---|---|---|---|
| 地面 | `false` | `false` | 被呼叫 | `jumpPressedThisFrame = true` → 跳躍 ✅ |
| 飛行 | `true` | `true` | 不呼叫 | 不跳躍，`isFlyUpHeld = true` → 上升 ✅ |

**飛行時不跳躍的理由**：`FlyingMovementNode.performMovementStep` 在 `isFlying` 時不呼叫 `super`，所以 `jumpPressedThisFrame` 本來就不會被消費。但若落地瞬間 `isFlying` 變 `false` 而 `jumpPressedThisFrame` 仍是 `true`，會觸發一次意外跳躍。吞掉更安全。

### 修正 3：`MyGameMode` 同步 `isFlying` 到 controller

**檔案**：`src/game/MyGameMode.ts`

`handleAction` 的 `toggleFlight` 分支（第 893-895 行）：

```typescript
case 'toggleFlight':
  this.isFlying = !this.isFlying;
  this.getPlayerPawn()?.setFlying(this.isFlying);
  if (this.localController) {
    this.localController.isFlying = this.isFlying;
  }
  break;
```

`updateFlight()` 的落地同步（第 587-590 行）：

```typescript
if (!pawn.isFlying) {
  // Landing cancels flight inside the movement node; mirror that here so the
  // game mode flag never drifts out of sync with the pawn.
  if (this.isFlying) {
    this.isFlying = false;
    if (this.localController) {
      this.localController.isFlying = false;
    }
  }
  return;
}
```

**為什麼需要兩處同步**：`toggleFlight` 是玩家主動切換，`updateFlight` 是落地自動取消。兩條路徑都會改變 `isFlying`，都必須鏡射到 controller。

## 驗證

### 單元測試（新增）

**檔案**：`tests/input/keyBindings.unit.ts`

| 測試 | 斷言 |
|---|---|
| `flyDown` 按 Ctrl 觸發 | `matchesBinding('flyDown', { code: 'ControlLeft', ctrlKey: true, ... }) === true` |
| `flyDown` 按 Ctrl 右鍵觸發 | `matchesBinding('flyDown', { code: 'ControlRight', ctrlKey: true, ... }) === true` |
| `undo` 按 Ctrl+Z 仍觸發 | `matchesBinding('undo', { code: 'KeyZ', ctrlKey: true, ... }) === true` |
| `undo` 按 Z 不觸發 | `matchesBinding('undo', { code: 'KeyZ', ctrlKey: false, ... }) === false` |
| `toggleBuildMode` 按 Ctrl+B 不觸發 | `matchesBinding('toggleBuildMode', { code: 'KeyB', ctrlKey: true, ... }) === false` |
| `toggleBuildMode` 按 B 觸發 | `matchesBinding('toggleBuildMode', { code: 'KeyB', ctrlKey: false, ... }) === true` |
| `flyDown` 按 Alt+Ctrl 不觸發 | `matchesBinding('flyDown', { code: 'ControlLeft', ctrlKey: true, altKey: true, ... }) === false` |

**注意最後一項**：`MODIFIER_CODES` 短路會讓 `altKey` 檢查被跳過。需要決定：Alt+Ctrl 是否該觸發 `flyDown`？

**建議**：不該。Alt 是上帝視角的環繞修飾鍵（見 [[上帝視角相機設計]]），Alt+Ctrl 應該是「環繞 + 下降」的組合，不該被 `flyDown` 吃掉。

所以短路要保留 `altKey` 檢查：

```typescript
if (MODIFIER_CODES.has(e.code)) {
  return !e.altKey;
}
```

### 手動驗證

| 步驟 | 預期 |
|---|---|
| 地面按 Space | 跳躍 |
| 快速按兩次 Space | 進入飛行 |
| 飛行中按 Space | 上升 |
| 飛行中按 Ctrl | 下降 |
| 飛行中按 Ctrl 直到落地 | 自動退出飛行 |
| 落地後按 Space | 跳躍（不是上升） |

## 風險與注意事項

| 風險 | 說明 | 緩解 |
|---|---|---|
| **`MODIFIER_CODES` 短路影響其他動作** | 若未來有人把 `undo` 綁到 `ControlLeft`，行為會改變 | 目前無此綁定；短路只影響「綁定鍵本身是修飾鍵」的情況 |
| **`isFlying` 雙向同步可能漂移** | `MyGameMode.isFlying` 與 `pawn.isFlying` 是兩個來源 | `updateFlight()` 每幀檢查 `pawn.isFlying`，發現不一致就同步 |
| **雙擊偵測與跳躍的競態** | 第一次 Space 觸發跳躍，第二次 Space 在 300ms 內觸發飛行 | 這是預期行為（Minecraft 也是這樣） |
| **`isFlyUpHeld` 在跳躍時被設為 `true`** | 地面按 Space 會設 `isFlyUpHeld = true`，但 `updateFlight()` 在 `!pawn.isFlying` 時直接 return，不會用到 | 無害 |

## 與 F3 按鍵顯示的關係

使用者提出「在 F3 加按鍵顯示」以便定位問題。這是**診斷工具**，與本修正**獨立**：

- 本修正解決已知的兩個 bug
- F3 按鍵顯示是未來除錯的基礎設施

**建議順序**：先做本修正（已知根因，改動小），再做 F3 按鍵顯示（需要新增 `InputTrace` 類別 + 改 4 個檔案）。

若先做 F3 顯示，可以用它驗證本修正是否生效 — 但這會讓修正的驗證依賴新工具，增加複雜度。
