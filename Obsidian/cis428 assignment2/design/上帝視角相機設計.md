# 上帝視角（God View）相機 — 設計與實作計劃

> 相關：[[方塊系統實作規格書]]、[[方塊系統重構設計]]、[[P2 建造系統]]

## 問題陳述

`CameraMode.GodView` 目前只是個 enum 值，**沒有任何地方根據它切換相機**。按 Tab 切換後：

- 畫面完全不變（仍是第一人稱相機）
- 準心消失、放置預覽出現（只有這兩處讀 `cameraMode`）
- 射線仍從第一人稱相機的螢幕中心射出

目標：實作一個**固定俯視角**的建造相機，讓玩家能用滑鼠直接點選方塊。

## 設計演進紀錄

| 版本 | 方案 | 結果 |
|---|---|---|
| v1 | Unity/Blender 完整編輯器：右鍵拖曳旋轉 + 中鍵平移 + 滾輪 dolly + Alt 環繞 | ❌ 右鍵與「放置方塊」衝突 |
| v2 | 空白鍵 + 右鍵/左鍵作旋轉/平移前置鍵（TSB GameMaker 風格） | ❌ `Space` 已是跳躍/飛行上升 |
| v3 | 固定俯視角 + Q/E 水平轉向 + WASD 平移 + Space/Ctrl 升降 | ❌ `E` 撞 `openPalette`；升降與飛行綁定重疊 |
| **v4（採用）** | **固定俯視角 + 中鍵水平轉向 + Alt+中鍵環繞轉向 + WASD 平移** | ✅ 無按鍵衝突 |

**v1 廢棄原因**：右鍵同時要「拖曳旋轉」與「點擊放置」，只能靠拖曳距離門檻區分，語意模糊且手感差。

**v2 廢棄原因**：`Space` 已綁 `toggleFlight` / `flyUp`，`Ctrl` 已綁 `flyDown`。加前置鍵會與飛行系統衝突。

**v3 廢棄原因**：`E` 已綁 `openPalette`；且使用者指出上帝視角**不需要垂直升降**（俯視角下升降意義不大，滾輪 dolly 已能調整距離）。

## v4 目標行為

### 相機姿態

**固定俯視角**：pitch 鎖定在 `-60°`（往下看 60 度），玩家**不能改變俯仰角**。

```
        camera
          ●
           \
            \  -60°
             \
              ▼
    ──────────────────  地面
```

這讓「滑鼠點到哪裡 = 方塊在哪裡」的對應關係保持直觀，也避免玩家把相機轉到水平而失去俯視優勢。

### 操作表

| 操作 | 行為 | 衝突檢查 |
|---|---|---|
| Tab | 切換第一人稱 ↔ 上帝視角 | 無 |
| 滑鼠移動 | 游標可見，選取框跟隨游標（射線從滑鼠 NDC 射出） | 無 |
| 左鍵 | 破壞方塊 | 無 |
| 右鍵 | 放置方塊 | 無 |
| WASD | 水平移動（沿 yaw 的前/後/左/右） | 無（上帝視角下 WASD 不驅動 pawn） |
| **中鍵拖曳** | **水平轉向（look）** — 相機原地旋轉 yaw | ✅ 中鍵原本空著 |
| **Alt + 中鍵拖曳** | **環繞轉向（orbit）** — 相機繞注視點旋轉 | ✅ Alt 未被佔用 |
| 滾輪 | 沿視線方向前進/後退（dolly） | 無 |

**沒有垂直升降** — 俯視角下升降意義不大，滾輪 dolly 已能調整與地面的距離。

### 為什麼中鍵可以空出來

v1 的設計裡中鍵是「平移」。但 v4 用 **WASD 做平移**，中鍵就空出來了。而中鍵在瀏覽器裡預設是「自動滾動」，只要 `preventDefault()` 就能完全接管。

### 水平轉向的兩種語意（兩者都實作）

| 方式 | 觸發 | 相機位置 | 視線方向 | 用途 |
|---|---|---|---|---|
| **A. 視角轉向**（look） | 中鍵拖曳 | 不動 | 改變 | 原地轉頭看四周 |
| **B. 環繞轉向**（orbit） | Alt + 中鍵拖曳 | 沿圓弧移動 | 始終指向注視點 | 繞著自己的建築轉一圈 |

**注視點（pivot）的選擇**：

| 候選 | 優點 | 缺點 |
|---|---|---|
| 玩家腳下 | 固定、可預測 | 建築離玩家遠時不好用 |
| 選取方塊 | 直觀、跟著滑鼠 | 滑鼠移出方塊時 pivot 會跳 |
| 相機前方固定距離的點 | 平滑、無跳動 | **pivot 隨 dolly 漂移**（見下節） |
| **視線與地面的交點** | pivot 永遠在地面、隨 dolly 自然靠近 | 需要處理 `forward.y ≈ 0` 的邊界 |

#### 為什麼不用「相機前方固定距離的點」

初版設計用 `ORBIT_DISTANCE = 20` 公尺，但這有個致命缺陷：**pivot 是相對相機計算的，所以滾輪 dolly 會讓 pivot 跟著漂移**。

假設建築在 `(0, 0, 0)`，相機在 `(0, 10, 20)`：

| 步驟 | 相機位置 | pivot（前方 20m） | 實際繞的圓心 |
|---|---|---|---|
| 初始 | `(0, 10, 20)` | `(0, -7.3, 10)` | 建築附近 ✅ |
| 滾輪前進 10m | `(0, 1.3, 10)` | `(0, -16, 0)` | 建築正下方 ⚠️ |
| 滾輪後退 10m | `(0, 18.7, 30)` | `(0, 1.4, 20)` | 建築後方 ⚠️ |

三個問題：

1. **圓心不固定** — 每次 orbit 都重新計算，連續 orbit 時圓心會漂移
2. **pivot 可能在地下** — `forward` 有 -60° 的向下分量，20 公尺後 Y 會很低
3. **pivot 與視線脫節** — 玩家以為在繞建築，實際繞的是空中的點

#### v4 採用「視線與地面的交點」

```typescript
private computeOrbitPivot(position: THREE.Vector3): THREE.Vector3 {
  const forward = new THREE.Vector3(0, 0, -1)
    .applyEuler(new THREE.Euler(FIXED_PITCH, this.yaw, 0, 'YXZ'));
  // pitch 固定 -60°，forward.y ≈ -0.866，不會是 0
  const t = Math.max(0, -position.y / forward.y);
  return position.clone().addScaledVector(forward, t);
}
```

**優點**：

1. **pivot 永遠在地面**（`y = 0`），符合「繞著地面上的建築轉」的直覺
2. **dolly 靠近時 pivot 自動靠近** — 因為視線角度固定，交點會隨相機位置移動，這才是正確的 orbit 行為（就像 Blender 的 orbit 圓心固定在地面，滾輪改變距離）
3. **不需要額外狀態** — 每幀從相機位置與 yaw 重新計算，沒有「pivot 過期」的問題
4. **不需要「重設 pivot」機制** — WASD 移動後 pivot 自動跟上

**邊界處理**：

| 情況 | `forward.y` | `t` | 處理 |
|---|---|---|---|
| 正常俯視（-60°） | `-0.866` | 正數 | 正常 |
| 相機在地面以下 | `-0.866` | 負數 | `Math.max(0, ...)` → pivot 在相機位置 |
| pitch 接近 0（未來若開放調整） | `≈ 0` | `∞` | 需 clamp `t` 上限（v4 pitch 鎖死，不會發生） |

環繞公式（繞 Y 軸）：

```typescript
const pivot = this.computeOrbitPivot(position);

// 繞 Y 軸旋轉 delta 角
const offset = position.clone().sub(pivot);
offset.applyAxisAngle(UP, deltaYaw);
position.copy(pivot).add(offset);

// yaw 同步改變，讓視線仍指向 pivot
this.yaw += deltaYaw;
```

因為 pitch 固定，且 offset 只在水平面旋轉，所以視線會自動保持指向 pivot。

## 架構決策

### 1. 新增 `GodViewCamera`，不複用 `FreeCamera`

`FreeCamera` 是除錯工具（F3+C），語意是「脫離 pawn 自由飛」，pitch 可自由調整。上帝視角是建造工具，pitch **鎖死**，且需要滑鼠點選。

兩者輸入模型不同，混用會讓程式碼充滿 `if (isGodView)` 分支。

但**複用 `ViewTargetCameraNode` 的 stack 機制** — 這是引擎提供的正確槓桿。

### 2. 相機互斥

`World.getActiveCamera()` 讀 stack 頂端。若 `FreeCamera` 和 `GodViewCamera` 同時 push，行為不可預測。所以：

- 進入上帝視角 → 若 FreeCamera 啟用則先 `deactivate()`
- 按 F3+C → 若在上帝視角則先退出上帝視角

### 3. Pointer lock 完全關閉

上帝視角**永遠不需要 pointer lock**：

- 游標必須可見（要點方塊）
- 旋轉靠中鍵拖曳，用 `movementX` 而非 `clientX` 差值
- 平移靠 WASD

所以進入上帝視角時 `exitPointerLock()`，離開時 `requestPointerLock()`。

**中鍵拖曳不需要 pointer lock** — `MouseEvent.movementX/Y` 在非 pointer lock 狀態下仍然有效（瀏覽器提供的是相鄰兩次 `mousemove` 的差值）。這點已從 `InputManager.handleMouseMove` 的實作確認：它把原始 `MouseEvent` 直接傳給 handler，`movementX/Y` 可用。

### 4. 射線來源依模式分流

`updateTargeting()` 目前固定用 `SCREEN_CENTRE`。改為：

```typescript
const ndc = this.cameraMode === CameraMode.GodView
  ? this.getMouseNdc()      // world.inputManager.getMousePosition()
  : SCREEN_CENTRE;
```

`InputManager.getMousePosition()` 已回傳 NDC（`x: -1..1`，`y: -1..1`，y 軸向上），與 `THREE.Raycaster.setFromCamera()` 的期望一致。

## 實作步驟

### 步驟 1：新增 `src/camera/GodViewCamera.ts`

```typescript
/** Fixed downward pitch, in radians. -60° keeps the ground readable. */
const FIXED_PITCH = -Math.PI / 3;

/** Metres per second at full stick. */
const MOVE_SPEED = 12;

/** Radians per pixel of middle-drag. */
const LOOK_SENSITIVITY = 0.005;

/** Metres per wheel notch. */
const DOLLY_STEP = 1.5;

const UP = new THREE.Vector3(0, 1, 0);

/** Input state the game mode feeds in each frame. */
export interface GodViewCameraInput {
  /** -1 back, 0 none, +1 forward. */
  forward: number;
  /** -1 left, 0 none, +1 right. */
  right: number;
  /** Middle-drag delta in pixels since the last frame. */
  lookDeltaX: number;
  /** True while Alt is held — switches middle-drag from look to orbit. */
  isOrbiting: boolean;
  /** Wheel notches since the last frame. */
  dolly: number;
}

export const IDLE_GOD_VIEW_INPUT: Readonly<GodViewCameraInput> = Object.freeze({
  forward: 0, right: 0, lookDeltaX: 0, isOrbiting: false, dolly: 0,
});

export class GodViewCamera {
  static create(world: ENGINE.World, fov: number): GodViewCamera;
  activate(position: THREE.Vector3, yaw: number): void;
  deactivate(): void;
  update(deltaTime: number, input: GodViewCameraInput): void;
  getPosition(): THREE.Vector3;
  getYaw(): number;
  getPitch(): number;
  destroy(): void;
}
```

**與 `FreeCamera` 的差異**：

| 項目 | FreeCamera | GodViewCamera |
|---|---|---|
| pitch | 滑鼠控制，可自由調整 | **鎖死 `-60°`** |
| 前進方向 | 只跟 yaw（水平） | 只跟 yaw（水平）— 相同 |
| 轉向 | 滑鼠 delta（pointer lock） | **中鍵拖曳 delta**（無 pointer lock） |
| 環繞 | 無 | **Alt + 中鍵** |
| 縮放 | 無 | 滾輪 dolly |
| 垂直 | Space/Ctrl | **無** |

**移動公式**（水平，與 `FreeCamera` 相同）：

```typescript
const step = MOVE_SPEED * deltaTime;
const sin = Math.sin(this.yaw);
const cos = Math.cos(this.yaw);
const dx = (-sin * input.forward + cos * input.right) * step;
const dz = (-cos * input.forward - sin * input.right) * step;
```

**轉向 / 環繞公式**：

```typescript
const deltaYaw = -input.lookDeltaX * LOOK_SENSITIVITY;

if (input.isOrbiting) {
  // Orbit: rotate the camera position around the point where the view ray
  // meets the ground plane. That pivot is recomputed every frame, so dolly
  // and WASD naturally move it — no stale state to reset.
  const pivot = this.computeOrbitPivot(position);
  const offset = position.clone().sub(pivot).applyAxisAngle(UP, deltaYaw);
  position.copy(pivot).add(offset);
}

this.yaw += deltaYaw;
```

**Pivot 計算**：

```typescript
private computeOrbitPivot(position: THREE.Vector3): THREE.Vector3 {
  const forward = new THREE.Vector3(0, 0, -1)
    .applyEuler(new THREE.Euler(FIXED_PITCH, this.yaw, 0, 'YXZ'));
  // FIXED_PITCH is -60°, so forward.y ≈ -0.866 and never reaches 0.
  // The clamp only guards against a camera that has sunk below the ground.
  const t = Math.max(0, -position.y / forward.y);
  return position.clone().addScaledVector(forward, t);
}
```

**Dolly 公式**（沿視線方向，含 pitch）：

```typescript
const forward = new THREE.Vector3(0, 0, -1)
  .applyEuler(new THREE.Euler(FIXED_PITCH, this.yaw, 0, 'YXZ'));
position.addScaledVector(forward, input.dolly * DOLLY_STEP);
```

**旋轉套用**：

```typescript
this.node.setWorldRotation(new THREE.Euler(FIXED_PITCH, this.yaw, 0, 'YXZ'));
```

public consumeGodViewLook(): number {
  const value = this.pendingGodViewLookX;
  this.pendingGodViewLookX = 0;
  return value;
}

  const value = this.pendingGodViewDolly;
  this.pendingGodViewDolly = 0;
  return value;
}

新增 `enterGodView()` / `exitGodView()`：

```typescript
private enterGodView(): void {
  const world = this.getWorld();
  const pawn = this.getPlayerPawn();
  if (!world || !pawn) return;

  if (!this.godViewCamera) {
    const active = world.getActiveCamera();
    const fov = active instanceof THREE.PerspectiveCamera ? active.fov : 75;
    this.godViewCamera = GodViewCamera.create(world, fov);
  }

  // Start above and behind the player, looking down at the build area.
  const position = pawn.getWorldPosition();
  position.y += GOD_VIEW_HEIGHT;
  position.z += GOD_VIEW_BACK;
  this.godViewCamera.activate(position, pawn.getWorldRotation().y);

  this.isGodViewActive = true;
  if (this.localController) this.localController.isGodViewEnabled = true;
  world.inputManager.exitPointerLock();
}

private exitGodView(): void {
  this.godViewCamera?.deactivate();
  this.isGodViewActive = false;
  if (this.localController) this.localController.isGodViewEnabled = false;
  this.getWorld()?.inputManager.requestPointerLock({ unadjustedMovement: true });
}
```

新增 `updateGodViewCamera(deltaTime)`（在 `tickPrePhysics` 呼叫，位置在 `updateFreeCamera` 之後）：

```typescript
private updateGodViewCamera(deltaTime: number): void {
  const camera = this.godViewCamera;
  const controller = this.localController;
  if (!camera || !this.isGodViewActive || !controller) {
    controller?.consumeGodViewLook();
    controller?.consumeGodViewDolly();
    return;
  }

  const input = controller.getInputManager();
  const frame: GodViewCameraInput = {
    forward: readAxis(input, 'godViewForward', 'godViewBack'),
    right: readAxis(input, 'godViewRight', 'godViewLeft'),
    lookDeltaX: controller.consumeGodViewLook(),
    isOrbiting: input?.isKeyDown('Alt') ?? false,
    dolly: controller.consumeGodViewDolly(),
  };
  camera.update(deltaTime, frame);
}
```

## 風險與注意事項

| 風險 | 說明 | 緩解 |
|---|---|---|
| **中鍵預設行為** | 瀏覽器中鍵會觸發自動滾動 | `handleMouseDown` 內 `e.preventDefault()` |
| **`movementX` 在非 pointer lock 下的可靠性** | 部分瀏覽器在非 lock 時 `movementX` 可能為 0 | 備援：若 `movementX === 0` 且 `clientX` 有變化，用 `clientX` 差值 |
| **Alt 鍵觸發瀏覽器選單** | Windows 上單按 Alt 會聚焦選單列 | `handleKeyDown` 攔截 `AltLeft`/`AltRight` 並 `preventDefault()` |
| **WASD 驅動 pawn** | 引擎的 `DefaultPlayerController` 會把 WASD 送給 pawn | `isGodViewAxis` 攔截後回傳 `true`，pawn 收不到 |
| **Pointer lock 時序** | `requestPointerLock()` 是異步的，可能被瀏覽器拒絕 | 失敗時靜默忽略 |
| **相機初始位置** | 從玩家位置往後上方 | `GOD_VIEW_HEIGHT = 10`、`GOD_VIEW_BACK = 10` |
| **環繞時 pivot 在地面** | pivot 取視線與 `y = 0` 的交點，若地形有高低差，pivot 可能落在山丘內部 | v4 不做地形高度查詢，可接受（編輯器相機通常可穿牆） |
| **相機沉到地面以下** | `t` 會變負數，pivot 跑到相機後方 | `Math.max(0, ...)` clamp，pivot 退化為相機位置（orbit 變成原地轉向） |

## 未來擴充（v4 不做）

| 項目 | 說明 |
|---|---|
| **可調 pitch** | 允許 `-30°` ~ `-90°` 之間調整 |
| **速度隨高度變化** | 相機越高移動越快 |
| **正交投影切換** | 需要第二個相機，v4 只用透視 |

| **環繞 pivot 可選** | 讓玩家選「玩家腳下 / 選取方塊 / 固定距離」 |
