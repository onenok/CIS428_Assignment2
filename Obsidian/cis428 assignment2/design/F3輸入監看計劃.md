# F3「Input」區塊 — 設計與實作計劃

> 相關：[[跳躍與飛行修正計劃]]、[[上帝視角相機設計]]
>
> **狀態：🟢 已實作**（`src/debug/InputTrace.ts`、`DebugSnapshot.ts`、`debugFormat.ts`、`MyPlayerController.ts`、`MyGameMode.ts`；測試 `tests/debug/inputTrace.unit.ts`、`tests/debug/debugFormat.unit.ts`）

## 問題陳述

除錯輸入問題時，F3 面板看不到任何輸入資訊。以 `flyDown` 不觸發為例，可能的失敗點有三個，但面板無法區分：

| 失敗點 | 症狀 | 現有面板能否判斷 |
|---|---|---|
| 1. 瀏覽器沒送 `keydown` | 完全沒反應 | ❌ |
| 2. `InputManager` 沒派發給 handler | 完全沒反應 | ❌ |
| 3. `matchesBinding()` 回傳 `false` | 完全沒反應 | ❌ |
| 4. `MyGameMode` 的 phase gate 吞掉 | 完全沒反應 | ❌ |

**四種失敗的症狀完全相同**，只能靠讀原始碼推測。F3「Input」區塊要讓這四種情況在畫面上可區分。

## 目標

在 F3 面板新增一個 `--- Input ---` 區塊，顯示三類資訊：

| 資訊 | 回答的問題 |
|---|---|
| **按住的鍵** | 瀏覽器有沒有送 `keydown`？`InputManager` 有沒有記錄？ |
| **按住的滑鼠鍵** | 同上，滑鼠版 |
| **最近觸發的動作** | `matchesBinding` 有沒有通過？`MyGameMode` 有沒有真的執行？ |

### 顯示範例

**Bug 重現時**（按 Ctrl 但 `flyDown` 沒觸發）：

```
--- Input ---
Keys: ControlLeft
Mouse: -
Actions: toggleFlight(2.3s)
```

→ 結論：`ControlLeft` 有被偵測到（失敗點 1、2 排除），但 `flyDown` 沒出現在 Actions（失敗點 3 或 4）。

**修好後**：

```
--- Input ---
Keys: ControlLeft KeyW
Mouse: -
Actions: flyDown(0.1s) toggleFlight(2.3s)
```

### 為什麼「最近動作」是關鍵

單看「按住的鍵」只能確認事件有到，無法判斷 `matchesBinding` 的結果。加上動作記錄就能直接定位：

- 按鍵有出現、動作沒出現 → `matchesBinding` 或 phase gate 的問題
- 按鍵沒出現 → 事件層的問題

## 架構決策

### 1. 新增 `InputTrace`，不直接讀 `InputManager`

`InputManager.keys` 是 **private**（`InputManager.d.ts:222`），沒有公開存取器。而且它只記錄「按住的鍵」，不記錄「觸發了什麼動作」。

`InputTrace` 是我們自己的資料類別，同時記錄兩者。

### 2. 寫入點在 `MyPlayerController`，不在 `MyGameMode`

`MyPlayerController` 是唯一知道「`matchesBinding` 通過了」的地方。若在 `MyGameMode` 寫入，就無法區分「`matchesBinding` 失敗」與「phase gate 吞掉」。

**但 `MyGameMode` 也要寫入** — 用來記錄「動作被 phase gate 擋下」。這樣才能區分失敗點 3 與 4。

### 3. 純資料類別，不碰 DOM

`InputTrace` 只做 `Set` 與陣列操作，可在 headless 測試中驗證。格式化留給 `debugFormat.ts`。

### 4. 時間用 `performance.now()`

`TracedAction.atMs` 存絕對時間，格式化時算 `ageMs = now - atMs`。這樣「0.1s 前」會隨時間更新，不需要每幀重寫記錄。

## 實作步驟

### 步驟 1：新增 `src/debug/InputTrace.ts`

```typescript
/**
 * Records what the input layer saw, for the F3 overlay.
 *
 * The overlay has to answer two different questions that a key list alone
 * cannot separate:
 *
 *   "did the key reach the handler?"   -> `heldKeys`
 *   "did the handler decide to act?"   -> `recentActions`
 *
 * A key that is held but never produces an action means the binding check or a
 * phase gate rejected it — which is exactly the bug class this exists to find.
 *
 * Pure data: no DOM, no engine types, so it runs in the headless harness.
 */

/** One action that fired, with the timestamp it fired at. */
export interface TracedAction {
  /** Action name, e.g. `flyDown` or `toggleFlight`. */
  readonly name: string;
  /** `performance.now()` at the moment it fired. */
  readonly atMs: number;
}

/** How many actions to keep. Older entries are dropped. */
const HISTORY_LIMIT = 8;

export class InputTrace {
  private readonly heldKeys = new Set<string>();
  private readonly heldMouse = new Set<number>();
  private readonly recent: TracedAction[] = [];

  /** Records a key press. */
  public keyDown(code: string): void {
    this.heldKeys.add(code);
  }

  /** Records a key release. */
  public keyUp(code: string): void {
    this.heldKeys.delete(code);
  }

  /** Records a mouse button press. */
  public mouseDown(button: number): void {
    this.heldMouse.add(button);
  }

  /** Records a mouse button release. */
  public mouseUp(button: number): void {
    this.heldMouse.delete(button);
  }

  /** Records that `name` fired at `nowMs`. */
  public action(name: string, nowMs: number): void {
    this.recent.push({ name, atMs: nowMs });
    if (this.recent.length > HISTORY_LIMIT) {
      this.recent.shift();
    }
  }

  /** Currently held key codes, sorted for a stable readout. */
  public get keys(): readonly string[] {
    return [...this.heldKeys].sort();
  }

  /** Currently held mouse buttons, sorted. */
  public get mouse(): readonly number[] {
    return [...this.heldMouse].sort((a, b) => a - b);
  }

  /** Recent actions, oldest first. */
  public get actions(): readonly TracedAction[] {
    return this.recent;
  }

  /**
   * Clears held state without touching history.
   *
   * The browser stops delivering `keyup` once focus leaves the window, so a key
   * held during Alt+Tab would otherwise stay "down" forever.
   */
  public clearHeld(): void {
    this.heldKeys.clear();
    this.heldMouse.clear();
  }

  /** Clears everything, including history. */
  public reset(): void {
    this.clearHeld();
    this.recent.length = 0;
  }
}
```

/** Human-readable name for a `MouseEvent.button` index. */
export function mouseButtonName(button: number): string {
  switch (button) {
    case 0: return 'left';
    case 1: return 'middle';
    case 2: return 'right';
    case 3: return 'back';
    case 4: return 'forward';
    default: return `button${button}`;
  }
}

lines.push('--- Input ---');
lines.push(`Keys: ${input.heldKeys.length > 0 ? input.heldKeys.join(' ') : '-'}`);
lines.push(`Mouse: ${input.heldMouse.length > 0 ? input.heldMouse.join(' ') : '-'}`);

### 步驟 6：`collectDebugSnapshot` 填入 input

**檔案**：`src/game/MyGameMode.ts`

```typescript
public collectDebugSnapshot(deltaTime: number): DebugSnapshot {
  // ...
  const now = performance.now();
  const trace = this.localController?.inputTrace;

  return {
    // ...
    input: {
      heldKeys: trace?.keys ?? [],
      heldMouse: (trace?.mouse ?? []).map(mouseButtonName),
      recentActions: (trace?.actions ?? []).map(action => ({
        name: action.name,
        ageMs: (now - action.atMs) / 1000,
      })),
    },
    // ...
  };
}
```

**注意單位**：`ageMs` 名稱是毫秒，但格式化時除以 1000 顯示為秒。為避免混淆，改名為 `ageSeconds`：

```typescript
export interface DebugInputAction {
  readonly name: string;
  /** Seconds since it fired. */
  readonly ageSeconds: number;
}
```

## 風險與注意事項

| 風險 | 說明 | 緩解 |
|---|---|---|
| **`performance.now()` 在 headless 環境** | Node 有 `performance` 全域（Node 16+） | 已確認可用；測試傳入固定值 |
| **每幀 `[...set].sort()` 配置** | 每幀配置 2 個陣列 | 只在 overlay 可見時呼叫（`updateDebugOverlay` 已檢查 `isVisible`） |
| **`inputTrace` 是 public 可變物件** | 外部可誤呼叫 `reset()` | 接受 — 這是除錯工具，不是 API |
| **13 處 `action()` 呼叫容易漏** | 新增動作時可能忘記記錄 | 在 `MyPlayerController` 加註解說明規則 |
| **`ageSeconds` 每幀變化** | 面板文字每幀都不同 | 已接受 — F3 面板本來就每幀更新 |

## 與跳躍與飛行修正的關係

**兩者獨立，但建議先做本計劃**：

| 順序 | 理由 |
|---|---|
| **先做 F3 Input** | 有了診斷工具，修正 `flyDown` 時能立即驗證「按鍵有到、binding 有過」 |
| 後做跳躍與飛行修正 | 修正後用 F3 面板確認 `Actions:` 出現 `flyDown` |

若先做修正，驗證只能靠「按 Ctrl 看角色有沒有下降」— 若沒下降，仍無法區分是 binding 還是 phase gate 的問題。
